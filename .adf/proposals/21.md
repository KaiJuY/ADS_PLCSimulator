# #21 Proposal：Editor 模組消除剩下的循環 import

## 1. Goal
#21（https://github.com/KaiJuY/ADS_PLCSimulator/issues/21）：搬移 `formatValue`、`decorateNode` 與 model 的 6 個查詢函式，讓 Editor 的模組圖沒有循環 import，並加一支檢查腳本證明。行為不變。

Issue 驗收條件（簡述）：
- AC1：`formatValue` 到 `variable.js`；`variable.js` 不 import `live.js`。
- AC2：`decorateNode` 到 `render.js`；`render.js` 不 import `live.js`。
- AC3：新增 `lookup.js`（只 import `state.js`）放 6 個查詢函式；`render.js` 不 import `model.js`。
- AC4：`.adf/evidence/21/cycles.mjs` 在新版輸出 0 個環，在 main 列出現有的環。
- AC5：只搬移。
- AC6：ESLint、load-graph、可達性、CDP 比對（#20 的 12 步，加 1 個讀值步驟與 3 個記錄：`liveValues`、`variableRead.value`、`variableRead.error`）。

背景：Editor 是 `src/AdsPlcSimulator.Host/wwwroot/editor/` 下的 ES module 圖，唯一進入點是 `index.html:81` 的 `<script type="module" src="editor.js">`。#11 拆檔（`.adf/proposals/11.md`）、#20 調整依賴方向（`.adf/proposals/20.md`）。#11 AC4 的規則：模組頂層只讀 `api.js`、`state.js` 的匯出與 function 宣告，所以現有循環能執行。ADF 階段：F 實作（implementer）、G 清理、H gate 與 reviewer、I 以使用者操作驗證（owner 以 CDP 腳本自動操作瀏覽器，不需要人手操作）（`C:\Users\AllenY\.claude\plugins\cache\adf\adf\0.2.4\references\flow.md`）。

只有 module 邊界改變。所有路徑都在 `src/AdsPlcSimulator.Host/wwwroot/editor/`。

搬移（逐字搬，含原有註解；搬出處整段刪除，連同其後的一個空行）：

|---|---|---|---|

- 用法：`node cycles.mjs <editor 資料夾>`。
- 讀資料夾內每個 `.js`，以 regex 逐行取出 `import ... from './x.js'` 與 `import './x.js'` 的目標（只取 `./` 開頭的相對路徑）。已知限制：只認單行 import，也會讀到註解裡的 import 字樣；寫在腳本第一行的用法註解。目前所有 import 都是單行、註解裡沒有 import 字樣。
- 模組名稱去掉 `.js`（輸出 `live`，不是 `live.js`）。
- 列出所有基本環（elementary cycle）：對每個起點 s，從 s 做 DFS，只走名稱字母序大於 s 的模組；「已在路徑上」只對目前路徑記錄（離開節點時移除，不做全域 visited）；走到 s 即記一個環。每個環印一行 `a -> b -> a`（從字母序最小的模組開始），依字串排序。
- 最後印 `cycles: <N>`；N > 0 時 exit code 1。

## 4. Behavior
- 依賴（main，`→` 表示 import，取自各檔 `^import` 行）：`state`→`api`；`view`→`state`；`variable`→`api`、`state`、`live`；`live`→`state`、`render`、`variable`；`render`→`state`、`model`、`live`、`view`、`variable`；`model`→`state`、`render`；`palette`→`api`、`state`、`model`、`view`；`canvas`→`state`、`model`、`render`、`palette`、`view`；`project`→`api`；`editor`→`project`、`api`、`state`、`model`、`render`、`palette`、`live`、`variable`、`canvas`（依此順序）。
- 依賴（新版）：`state`→`api`；`view`、`lookup`→`state`；`variable`→`api`、`state`；`render`→`state`、`lookup`、`view`、`variable`；`live`→`state`、`render`、`variable`；`model`→`state`、`lookup`、`render`；`palette`→`api`、`state`、`model`、`view`；`canvas`→`state`、`lookup`、`model`、`render`、`palette`、`view`；`project`→`api`；`editor`→ 全部。沒有環。
- main 上的環（`cycles.mjs` 的反證預期輸出）：`live -> render -> live`、`live -> render -> variable -> live`、`live -> variable -> live`、`model -> render -> model`，`cycles: 4`。
- 求值順序（ES module 從 `editor.js` 依 import 順序深度優先、後序求值；遇到正在處理中的模組略過）：
  - main：`api`、`project`、`state`、`variable`、`live`、`view`、`render`、`model`、`palette`、`canvas`、`editor`。推導：`editor`→`project`（→`api`）→`state`→`model`→`render`→`live`→`variable`（它 import 的 `live` 正在處理中，略過）所以 `variable` 先於 `live` 求值；之後 `view`、`render`、`model`。
  - 新版：`api`、`project`、`state`、`lookup`、`view`、`variable`、`render`、`model`、`palette`、`live`、`canvas`、`editor`。
  - 差異：`live` 移到 `palette` 之後；`variable` 移到 `view` 之後；新增 `lookup`。`live.js`、`render.js`、`model.js`、`lookup.js` 頂層只有 import 與宣告；`variable.js` 頂層只註冊 `#variablePath`、`#variableForm` 的事件，與其他模組註冊的元素不同。`view.js` 頂層只有 import 與宣告；`palette.js`、`canvas.js` 頂層註冊 `#canvas` 與 quick add 元素的事件，兩者相對順序不變（palette 仍在 canvas 之前）；`editor.js` 仍最後求值。所以順序改變不影響行為。
- 查詢函式是 `const`：搬到葉模組 `lookup.js` 後，它在所有使用者之前求值，沒有 TDZ 風險（現在它們在 `model.js`，被 `render.js` 在執行時才讀）。
- AC1：`variable.js:7`（`showVariable`）、`live.js:94`（sim log）、`render.js` 的 `decorateNode` 都呼叫 `variable.js` 的 `formatValue`。
- AC2：`render.js:54`（`createNodeElement`）與 `live.js:41,62` 呼叫 `render.js` 的 `decorateNode`。
