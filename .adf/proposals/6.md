# #6 Proposal：Host 執行器模式

Issue：https://github.com/KaiJuY/ADS_PLCSimulator/issues/6（驗收條件 AC 1–15 以 issue 為準，§4 有逐條對照）。

## 0. 名詞與現況

| 名詞 | 意思 |
|---|---|
| Core、Host | 兩個專案：`src/AdsPlcSimulator.Core`（PLC 宣告解析、記憶體、workflow 引擎，不碰 ADS 與 HTTP）、`src/AdsPlcSimulator.Host`（ASP.NET 程式：ADS server、HTTP API、Editor 網頁）。 |
| 專案 | 一個資料夾，底下有 `plc/`（PLC 宣告檔）、`workflows/`（`*.flow.json`），可選 `simulation/`（靜態網頁）。例：`projects/Polar2Chamber`。 |
| workflow | `workflows/*.flow.json` 描述的節點圖，由 Core 的 `FlowRuntime` 執行：依觸發條件（變數寫入、週期、啟動）跑節點，讀寫 process image，或送出 simulation 指令。執行中的 workflow 是 `FlowRuntime` 的背景 task。 |
| process image | 專案所有 PLC 變數的記憶體（`ProcessImage`，一個 byte 陣列），ADS 讀寫與 workflow 都操作它。每個 session 有自己的一份，不需要釋放（GC 回收）。 |
| simulation 指令 | workflow 送給 Simulation 網頁的 `(target, action, value)`，例 `("Chamber1.Door", "Open", null)`。介面 `ISimulationSink.Invoke`（Core）。 |
| `LiveHub` | Host 的 singleton，經 WebSocket `/live` 推送給瀏覽器：flow 事件（介面 `IFlowMonitor.Publish`，Editor 顯示 workflow 執行狀態）與 simulation 指令（Simulation 網頁）。它保存每個 target 的最後一筆 simulation 指令（`_simulationState`），新連線時重播（訊息 `simState`）。 |
| `ProjectsRoot` | 設定 `Simulator:ProjectsRoot`，Editor 從它底下列出專案。相對路徑以 Host 的 content root（`src/AdsPlcSimulator.Host`）為起點。 |
| Run／Stop | Run：載入一個專案並在 `Ads:Port` 註冊 ADS server。Stop：取消註冊 ADS port，停止 workflow，釋放專案。 |
| session | `SimulatorSession`：一個已載入專案的 symbol 表、process image、`FlowRuntime`。 |
| symbol version | ADS IG 0xF008 回的 1 byte，ADS client 用它判斷 symbol 表是否換過。值存在基底類別 `AdsSymbolicServer` 的 `protected byte symbolVersion` 欄位；#4（https://github.com/KaiJuY/ADS_PLCSimulator/issues/4）實作了 0xF008。 |
| CLI 路徑 | 啟動時設定的 `Simulator:ProjectPath`（命令列或環境變數）。 |
| 路由器模式 | `Ads:Router`：`Local`（預設，註冊到本機已安裝的 TwinCAT router）或 `Embedded`（Host 自己啟動 `AmsTcpIpRouter`，給沒有 TwinCAT 的機器；佔 TCP 48898）。 |
| AMS port | ADS 位址的一部分。本機 851、852 是另一個真 PLC 的 runtime，**不得使用**；模擬器預設 25860（#5）；單元測試用 25853–25855。 |
| U1、U2 | 實作單元：U1 = 後端（§2.1–§2.10），U2 = Editor 工具列（§2.11）。 |
| stage F／I | ADF（本 repo 的開發流程，記錄在 `.adf/`）的階段：F = 實作與單元測試；I = 以真實操作驗證（啟動 Host、ADS client、瀏覽器）。 |

**現況**（`b5ae1e4`）：
1. `Program.cs` 在啟動時從 DI 取得 `SimulatorSession`（singleton），其建構式依 `Simulator:ProjectPath`（程式內預設 `../../projects/RobustSolutionDemo`）建 `PlcProgram`、process image、`FlowRuntime`（monitor 與 simulation sink 都是 `LiveHub`），再建立 `workflows/` 並載入每個 `*.flow.json`。載入失敗 → Host 啟動失敗。
2. `AdsServerService`（`BackgroundService`）在 `Embedded` 模式先啟動路由器並等 `IsRunning`（失敗丟 `InvalidOperationException("The embedded AMS router could not start (is TwinCAT's router already using TCP 48898?)")`），再建立 `PlcAdsServer` 並 `ConnectServerAndWaitAsync` 到 Host 關閉；port 被佔用時只寫 log，Host 照常執行。關閉時 `router.Stop()` 並最多等路由器 task 5 s。
3. `Program.cs:23-30` 只在啟動時 `simulation/` 存在時，把 `/simulation` 掛到該資料夾。

## 1. 目標

#6：Host 啟動時不載入專案；使用者在 Editor 選專案按 Run／Stop，Host 在執行期間建立與釋放專案和 ADS server，並記住在 Editor 最後 Run 的專案。

```csharp
public sealed partial class SimulatorSession : IAsyncDisposable
{
    internal static readonly TimeSpan CleanupTimeout = TimeSpan.FromSeconds(5);

    public SimulatorSession(string projectDirectory, LiveHub liveHub, ILogger<SimulatorSession> logger);

    public string Name { get; }                  // Path.GetFileName(ProjectDirectory)
    public string ProjectDirectory { get; }      // Path.TrimEndingDirectorySeparator(Path.GetFullPath(projectDirectory))
    public PlcProgram Program { get; }
    public ProcessImage Image { get; }
    public FlowRuntime Runtime { get; }
    public IFileProvider SimulationFiles { get; } // simulation/ 存在 → PhysicalFileProvider；否則 NullFileProvider
    internal SessionLiveChannel Live { get; }     // §2.3
    // Workflows、ReadWorkflow、SaveWorkflow、IsValidWorkflowName 不變。
    // 刪除 SimulationDirectory（唯一使用者是 Program.cs:23-30）。
    public ValueTask DisposeAsync();             // Live.Close()；await Runtime.DisposeAsync()；SimulationFiles 若是 IDisposable 則 dispose

```

建構式順序：解析 `ProjectDirectory` → `PlcProgram.LoadDirectory` → `CreateProcessImage` → `Live = new SessionLiveChannel(liveHub)` → `Runtime = new FlowRuntime(Image, Program.Symbols, NodeCatalog.Default, Live, Live, ProjectDirectory)` → `SimulationFiles` → 建 `workflows/` 並載入 workflow。

- 建立 `FlowRuntime` 之前失敗：沒有需要清理的資源，例外直接丟出。
- 建立 `FlowRuntime` 之後失敗：catch 任何例外 → `Live.Close()` → `Runtime.DisposeAsync().AsTask().Wait(CleanupTimeout)`（逾時或例外 → Warning log `"Cleanup of {Directory} did not finish within 5 s."`）→ dispose `SimulationFiles` → 重新丟出原例外。

### 2.4 ProjectHost（Create `Project/ProjectHost.cs`）

```csharp
public enum ProjectState { Stopped, Running }
public enum RunOutcome { Started, AlreadyRunning, UnknownProject, Failed }
public sealed record RunResult(RunOutcome Outcome, string? Error);
public sealed record ProjectStatus(
    ProjectState State, IReadOnlyList<string> Projects, string? Running, string? RunningPath, string? Last, ushort Port);

/// <summary>Owns the running project and its ADS server. Run and Stop are serialized.</summary>
public sealed class ProjectHost : IAsyncDisposable
{
    public ProjectHost(IOptions<SimulatorOptions> options, IOptions<AdsOptions> adsOptions, IHostEnvironment environment,
        LiveHub liveHub, ProjectStateStore stateStore, ILoggerFactory loggerFactory);

    // 測試用（internal，init）：
    internal TimeSpan RegisterTimeout { get; init; } = TimeSpan.FromSeconds(5);
    internal TimeSpan StopTimeout { get; init; } = TimeSpan.FromSeconds(5);
    internal Func<PlcAdsServer, CancellationToken, Task> Connect { get; init; } = (server, token) => server.ConnectServerAsync(token);
    internal Func<SimulatorSession, ValueTask> DisposeSession { get; init; } = session => session.DisposeAsync();

    public string ProjectsRoot { get; }
    public SimulatorSession? Current { get; }         // Volatile.Read；null = Stopped
    public ProjectStatus GetStatus();
    public IReadOnlyList<string> ListProjects();
    public Task<RunResult> RunAsync(string? name);              // Editor
    public Task<RunResult> RunPathAsync(string projectDirectory); // CLI，任何路徑，不寫 state.json
    public Task StopAsync();
    public ValueTask DisposeAsync();

    internal static byte SymbolVersionForRun(int run); // run 從 1 起：((run - 1) % 255) + 1
}
```

- 建構式：`ProjectsRoot = Path.GetFullPath(Path.Combine(environment.ContentRootPath, options.Value.ProjectsRoot))`；`_logger = loggerFactory.CreateLogger<ProjectHost>()`；session 用 `loggerFactory.CreateLogger<SimulatorSession>()`；`_lastProject = stateStore.ReadLastProject()`。

- Create `Project/ProjectStartupService.cs`：

```csharp
/// <summary>Starts the embedded router when configured, runs the CLI project, and stops both on shutdown.</summary>
internal sealed class ProjectStartupService(ProjectHost host, IOptions<SimulatorOptions> options, IOptions<AdsOptions> adsOptions,
    IHostEnvironment environment, ILoggerFactory loggerFactory) : IHostedService
{
    private readonly CancellationTokenSource _routerStop = new();
    private AmsTcpIpRouter? _router;
    private Task _routerTask = Task.CompletedTask;

    public Task StartAsync(CancellationToken cancellationToken);
    public Task StopAsync(CancellationToken cancellationToken);
}
```

`StartAsync`（整段 try/catch：任何例外 → 停路由器（`StopRouterAsync`）→ 重新丟出）：
1. `Router == Embedded`：`_router = new AmsTcpIpRouter(AmsNetId.Parse(NetId), loggerFactory)`；`_routerTask = _router.StartAsync(_routerStop.Token)`（自己的 token）；`while (!_router.IsRunning && !_routerTask.IsCompleted) await Task.Delay(100, cancellationToken)`；迴圈結束時 `_routerTask` 已完成（失敗或正常結束）且 `IsRunning` 為 false → 丟 `InvalidOperationException("The embedded AMS router could not start (is TwinCAT's router already using TCP 48898?)", <task 的例外或 null>)`。無論有沒有 `ProjectPath` 都啟動（Editor Run 也需要路由器）。
2. `ProjectPath` 為 null 或空白 → 結束（Stopped）。
3. 否則 `host.RunPathAsync(Path.GetFullPath(Path.Combine(environment.ContentRootPath, ProjectPath)))`；`Failed` → 丟 `InvalidOperationException(result.Error)`。

`StopAsync`：`await host.DisposeAsync()`（§4.C，之後的 Run 一律 `Failed`）→ `StopRouterAsync()`。

`StopRouterAsync`：`_router?.Stop()`；`_routerStop.Cancel()`；`await _routerTask.WaitAsync(TimeSpan.FromSeconds(5))`，任何例外忽略（與現況相同）。

## 3. 資料與狀態

| 狀態 | 擁有者 | 誰改 | 執行緒 |
|---|---|---|---|
| `_current`、`_server`、`_runCount`、`_disposed`、`_pendingRelease`（`Task?`） | `ProjectHost` | 只有 RunCore／StopCore／DisposeAsync，在 `SemaphoreSlim(1,1)` 內；`WaitAsync` 之後整段 `try/finally { _gate.Release(); }` | request 執行緒、hosted service。`Current` 讀取不拿 semaphore（`Volatile.Read`） |
| `_lastProject` | `ProjectHost` | 建構時讀；Editor Run 成功時寫（semaphore 內） | `Volatile.Read` |
| `state.json` | `ProjectStateStore` | `WriteLastProject` | semaphore 內呼叫（本機小檔案，同步 IO） |
| `_closed` | `SessionLiveChannel` | `Close()` | workflow 執行緒讀；Stop／Run 失敗路徑寫 |
| `_simulationState` | `LiveHub` | `Invoke`（只經由未關閉的 `SessionLiveChannel`）、`ClearSimulationState` | workflow 執行緒、Run／Stop |
| 路由器 | `ProjectStartupService` | `StartAsync`／`StopAsync` | hosted service |

`_pendingRelease`：一個前一次 Run 失敗或 Stop 留下、尚未完成的 port 釋放（晚到的 connect 或卡住的 Disconnect）。

## 4. 行為

### A. Run

`RunAsync(name)`：name 為 null／空白或不在 `ListProjects()` → `UnknownProject`（不拿 semaphore）；否則 `RunCore(Path.Combine(ProjectsRoot, name), name, remember: true)`。
`RunPathAsync(path)`：`full = Path.TrimEndingDirectorySeparator(Path.GetFullPath(path))`；`RunCore(full, Path.GetFileName(full), remember: false)`。

RunCore(directory, name, remember)，在 semaphore 內：
1. `_disposed` → `Failed("The Host is shutting down.")`。`_current` 不為 null → `AlreadyRunning`。
2. `_pendingRelease` 不為 null：已完成 → 設 null；未完成 → `Failed("AMS port {Port} is still held by the previous project. Restart the Host.")`（log Error 同文）。
3. `liveHub.ClearSimulationState()`。
4. `version = SymbolVersionForRun(_runCount + 1)`。
5. `session = new SimulatorSession(directory, liveHub, sessionLogger)`。任何例外（`catch (Exception e) when (e is not OutOfMemoryException)`）→ session 建構式已自行清理（§2.2）→ log Error `"Run {Project} failed: {Message}"` → `Failed(e.Message)`。例：`plc/` 只有 TYPE → Error 原文含 `declares no global variables`。
6. `server = new PlcAdsServer(port, session.Program.Symbols, session.Image, loggerFactory, version)`。`using var cts = new CancellationTokenSource(RegisterTimeout)`（只用於連線；連線完成後取消或 dispose 對 server 無影響，C14）。`connect = Connect(server, cts.Token)`；`await connect.WaitAsync(RegisterTimeout)`。任何例外（`TimeoutException`、`OperationCanceledException`、`AdsServerException` 等）→ 失敗處理：
   1. `connect` 未完成 → 再等最多 `RegisterTimeout`（`connect.WaitAsync`，例外忽略）。
   2. `connect` 已完成 → `server.Dispose()`；仍未完成 → `_pendingRelease = connect.ContinueWith(_ => server.Dispose(), TaskScheduler.Default)`。
   3. `await DisposeSession(session).AsTask().WaitAsync(StopTimeout)`；逾時或例外 → Warning log。
   4. `liveHub.ClearSimulationState()`。
   5. log Error `"Run {Project} failed: AMS port {Port} could not be registered ({Message}). Is another runtime using this port?"` → `Failed(<同一段訊息>)`。
7. 成功：`_runCount++`；`_server = server`；`Volatile.Write(ref _current, session)`；`remember` → `stateStore.WriteLastProject(name)`、`_lastProject = name`；log Information `"Project {Project} running on AMS port {Port}, symbol version {Version}."` → `Started`。

### B. StopCore（semaphore 內）

1. `_current` 為 null → 回。
2. `Volatile.Write(ref _current, null)`（API 立刻回 409；port 到第 3 步完成才釋放，通常 < 100 ms）。
3. `release = Task.Run(() => { server.Disconnect(); server.Dispose(); })`；`await release.WaitAsync(StopTimeout)`；逾時 → `_pendingRelease = release`，log Error `"Stop {Project}: AMS port {Port} was not released within 5 s."`；其他例外 → log Error `"Stop {Project}: AMS port {Port} release failed ({Message})."`。`_server = null`。
4. `await DisposeSession(session).AsTask().WaitAsync(StopTimeout)`：session 的 `DisposeAsync` 先關閉 `SessionLiveChannel`，之後殘留的 workflow 送的 flow 事件與 simulation 指令都不會到 `LiveHub`。逾時 → log Warning `"Workflows of {Project} did not stop within 5 s; releasing anyway."`；其他例外 → log Warning。
5. `liveHub.ClearSimulationState()`。
6. log Information `"Project {Project} stopped; AMS port {Port} released."`（第 3 步失敗時改為 Warning `"Project {Project} stopped; AMS port {Port} may still be registered."`）。

### C. DisposeAsync

## 8. 考慮過的做法

issue #6「考慮過的做法」各項（全部不採用，理由見 issue）：launcher script 重啟 Host；Editor 輸入任意路徑；不帶參數時自動 Run 上次專案；state 檔放在 Host 執行目錄旁；Stopped 時可編 workflow；Stop 時保留 port 並回 ReadState Stop；每次 Run symbol version 回到 1；Running 時直接 Run 另一個專案；`/simulation` 只在 CLI 啟動時存在；CLI 自動 Run 也寫 state 檔。本 proposal 採用的是它們的相反做法（§2、§4）。

本 proposal 另外否決：
- **保留 `AdsServerService`（BackgroundService）並加重啟邏輯**：BackgroundService 只啟動一次，重啟要另外的 signal 與迴圈；`ProjectHost` 直接用 `ConnectServerAsync`／`Disconnect` 較單純（C1、C2）。
- **用 `ConnectServerAndWaitAsync` 加 `IsConnected` 輪詢**（現有寫法）：port 被佔用時只寫 log、不丟例外（#5 時以 851 實測：log `ClientPortNotOpen` 後 Host 照常啟動，https://github.com/KaiJuY/ADS_PLCSimulator/issues/5），Run 無法回 400。
- **Stop 時只呼叫 `LiveHub.ClearSimulationState()`**：殘留的 workflow 之後仍可寫回（C6），所以加 §2.3 的每 session 通道。
- **卡住的 port 自動重試釋放**：無法確定 TwinCAT router 何時放手；改為明確回「Restart the Host」（§4.A 第 2 步）。
- **Endpoint 測試用 `WebApplicationFactory`**：要新增 `Microsoft.AspNetCore.Mvc.Testing` 套件；handler 抽成 `internal static` 回 `IResult`，直接呼叫；空 body 的繫結由 stage I 第 5 步驗證。
- **Run／Stop 後 Editor 局部重載**：`editor.js` 已 1010 行，局部重載要改多處；`location.reload()` 只需 3 行掛鉤。
- **狀態值多 `Starting`／`Stopping`**：Run／Stop 在 semaphore 內依序執行，`GET` 回最後完成的狀態即可。

## 10. 風險

- **請求與 Stop 交錯**：端點讀到 `Current` 後 Stop 立即 dispose session。讀 process image 不受影響；`SaveWorkflow` 可能對已 dispose 的 runtime 呼叫 `Load`，回 500。`/simulation` 正在傳的檔案可能中斷（`GetFileInfo` 本身已處理 `ObjectDisposedException`）。機率低，不加鎖。
- **Stop 逾時**：不理會取消的 workflow 在 5 s 後仍可能執行，寫入舊 session 的 process image（新專案有自己的 image，不受影響）；它送出的 flow 事件與 simulation 指令被 §2.3 的通道擋下。
- **port 卡住**：Disconnect 逾時或晚到的 connect 未結束時，下一次 Run 回 400「Restart the Host」。
- **CLI 啟動行為改變**：不帶參數的 `dotnet run` 改為 Stopped，README 寫明。
- **測試反覆註冊 25855**：C2 顯示釋放後可立刻再註冊；`AdsServerTests.cs` 註解提到「每個測試重新註冊同一 port 會與釋放競爭」。若出現不穩定，原因在 port 釋放時機，處理方式是測試間等待 25855 回 `TargetPortNotFound` 再繼續。
- **Embedded 路由器沒有自動測試**：程式碼搬移，但啟動時機從 `ExecuteAsync` 改為 `StartAsync`。
- **state.json**：寫在使用者的 `%LOCALAPPDATA%`（stage I 會寫入實際檔案）；在 semaphore 內同步寫入；兩個 Host 同時執行時互相覆蓋（最後寫入者勝），`Last` 只在啟動時讀。
