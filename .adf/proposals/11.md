## 3. Data and state
- 共用的可變狀態只有 `state`、`els`，都在 `state.js`，不變。
- 只在單一模組內重新指派的 `let`：`symbolTimer`（render.js）、`variableTimer`（variable.js）；`quickAdd` 是 `const` 物件，只在 palette.js 內讀寫。
- 單執行緒（瀏覽器主執行緒），沒有新的狀態擁有者。

## 4. Behavior
- 載入順序：瀏覽器從 `editor.js` 深度優先走 import。進入點 `editor.js` 的本體最後執行，所以 `init()`（`editor.js:1015`）在所有模組的頂層程式都跑完後才呼叫。
- 循環 import：model↔render↔editor、canvas↔palette、live↔variable↔render 等都存在。規則（issue AC4）：模組頂層程式只讀 `api.js`、`state.js` 的匯出、自己的宣告與其他模組的 **function 宣告**。現有頂層程式（`canvas.js` 的三個 `els.canvas.addEventListener`、`palette.js` 的 dragover／drop／dblclick／contextmenu／quick add 註冊、`variable.js` 的三個註冊、`editor.js` 的鍵盤與工具列）只讀 `els`、`$` 與其他模組的 function 宣告（例如 `editor.js:995` 直接傳入 `renderPalette`），跨模組的 `const` 只在 callback 內使用，符合規則。
- `model.js` 的 `findNode` 等是 `const` 箭頭函式，跨模組使用都在 callback 或函式內（呼叫時所有模組都已求值），不在任何頂層程式中呼叫。
- 事件註冊的先後順序改變（依模組求值順序），但同一個目標的同一種事件只在一個模組註冊（`els.canvas` 的 pointerdown、wheel、pointermove 在 canvas.js；dragover、drop、dblclick、contextmenu 在 palette.js；`window` 的 keydown、beforeunload、resize 在 editor.js），所以觸發順序不變。

### 6.2 靜態檢查（stage F，implementer 跑；腳本放 `.adf/evidence/11/`）
1. `node --check <file>`：每個 `.js` 的語法。
2. 未宣告名稱：ESLint 9.17.0 的 `no-undef`，`sourceType: "module"`，globals 為瀏覽器用到的名稱（`document`、`window`、`location`、`fetch`、`WebSocket`、`CSS`、`Option`、`requestAnimationFrame`、`prompt`、`alert`、`confirm`、`URLSearchParams`、`setTimeout`、`clearTimeout`、`Map`、`JSON` 等 ES 內建由 `ecmaVersion: 2024` 提供）。安裝在 scratchpad（`npm i eslint@9.17.0`），不加入 repo。它抓 callback 內忘了 import 的名稱；這類錯誤只在執行到該路徑時才丟 `ReferenceError`，stage I 的流程不一定走到。基準：main 的 `editor.js`、`project.js` 先跑一次，必須 0 錯誤。
3. 真實模組圖載入：`.adf/evidence/11/load-graph.mjs` 把 `wwwroot/editor/*.js` 複製到暫存目錄（加一個 `{"type":"module"}` 的 `package.json`），在 Node 裡以 stub 取代 `document`（`getElementById`、`querySelector` 回傳可接受 `addEventListener`、`querySelectorAll`、`append` 等呼叫的假元素）、`window`、`location`、`WebSocket`、`fetch`（回傳不會 resolve 的 Promise，讓 `init()` 停在第一個 await），然後 `import` 暫存目錄的 `editor.js`。成功代表：所有 named import 都存在（缺的會是 link 時的 `SyntaxError`）、求值順序與 TDZ 沒問題、頂層程式沒碰未初始化的 binding。用 main 的檔案先跑一次確認 stub 足夠。

## 8. Alternatives
- 手動走過流程：不採用；CDP 自動比對可重跑，Allen 在 stage J 可另行手動檢查（grill Q3）。
- 拆 3–4 個大檔：不採用；現有 10 段已是職責邊界，依段拆最少判斷（grill Q1）。
- 只搬出 Live、PLC variable（`editor.js` 約 850 行）：不採用；檔案自 #6 起持續成長，下次加功能又會碰到上限（grill Q5）。
- 自寫 regex 腳本找漏掉的 import：不採用；字串、註解、屬性名會誤判。改用 ESLint `no-undef`（只裝在 scratchpad）。
- Running 畫面像素比對：不採用；`#runLog` 含時間、`.pulse` 有計時，改比對 DOM。
- `git checkout` 還原儲存過的 workflow：不採用，改存新的未追蹤檔再刪除。
- 把 `findNode` 等改成 function 宣告以完全避開 TDZ：不採用；違反「只搬移」，且 §4 已確認沒有頂層呼叫。
- 用 bundler：不採用；專案沒有前端建置流程，ES module 原生可用。

## 9. Out of scope
新功能、樣式、邏輯重構、改名；JS 測試框架；`editor.css`、`index.html`。

## 10. Risks
- 漏 import：瀏覽器在呼叫時才丟 `ReferenceError`（模組求值不會發現未使用的路徑）。由 §6.3 靜態檢查與 §6.2、§6.3 的 console 錯誤比對抓。
- 瀏覽器快取舊模組：使用者若沒強制重新整理，可能拿到新 `editor.js` 配舊的子模組（或反過來），在 link 時失敗。開發工具，風險低。測試時 headless Edge 每次用新的 user-data-dir。
- CDP 比對對時間敏感（live 事件、`requestAnimationFrame`）：每步之後等固定時間並以 DOM 狀態為準，不比對 `#runLog` 文字（含時間）。
