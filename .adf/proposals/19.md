# Proposal #19：Polar2 service 自訂行為第 4 批（SingleProcess、CupChamberClean 步驟模擬）

## 1. 目標
#19（https://github.com/KaiJuY/ADS_PLCSimulator/issues/19）：Core 新增通用的步驟執行器；`service-behaviors.json` 的 service 項目新增 `process` 設定段；Polar2 的 `Chamber.SingleProcess`、`Chamber.CupChamberClean` 依設定在進入 Execute 時檢查步驟參數，依每步的 `ProcessTime` 執行（循環可巢狀），每步寫轉速與供液 SVID（CupChamberClean 另寫 Cup 高度），結束或離開 Execute 時寫 0。

issue 的驗收條件（AC，編號同 issue）：
- AC1 範圍；AC2 通用執行器與 `process` 段；AC3 Run 驗證、`process` 與 `duration` 互斥、`schemaVersion` 1；AC4 公開型別只新增。
- AC5–AC9 參數檢查（步數、每步欄位、循環配對、CleanSettings、Message 格式）。
- AC10 循環語意；AC11 總時間；AC12 每步的 SVID（含 RotateSpeed 四捨五入、`dryRunZero`）；AC13 Cup 高度；AC14 結束、離開 Execute、Unhold；AC15 逐步推進與狀態清除；AC16 被 workflow 接管時不執行。
- AC17 單元測試；AC18 Integration S34–S37；AC19 不量測真 PLC。

名詞與現行行為見 `.adf/proposals/16.md` §1、`.adf/proposals/17.md` §1、`.adf/proposals/18.md` §1：Run、PackML 狀態與一次 scan 的順序、ServiceCtrl／ServiceStatus／ServiceParam、bound service、錯誤碼表、DryRun、SVID／ECID 的陣列位置、`ServiceRules`、onEnter／beforeComplete／onLeave、REAL／DINT 寫入格式。本 proposal 補充：
- **步驟路徑**：`process` 段中的欄位路徑相對於 `ServiceParam.<service>`，可含字面 `[i]`，代表「第 i 步」；Core 以 i = 1..`maxCount` 取代後解析。例：`ProcessSteps[i].ArmIndex`、`CleanSettings[i].TargetCupIndex`、`ProcessSteps[i].FixedNozzleSetpoint[2]`。沒有 `[i]` 的路徑（例 `RecipeCount`）只解析一次。
- **執行（run）**：一次從 Starting 進入 Execute 的步驟執行；狀態是目前步驟、循環堆疊、該步開始時間、目前步驟寫過的 SVID。
- **共用 SVID**（#18 AC7，`.adf/proposals/18.md` §2.2）：同一個 SVID 由多個 service 寫入時沒有擁有者檢查；兩個 service 同時在 Execute 時，先離開的寫 0；模擬器不阻擋同時執行。
- **Mode 值**：0 Disable、1 Manual（不允許 SingleProcess、EMGS）、2 DryRun、3 Auto（`config/service-behaviors.json` 的 `modes`）。
- **流程用語**：stage A–J 是 ADF 流程的階段（B 拆分、C 本文件、D 審查、F 實作、I 整合測試）；owner 是主持流程的主 agent；reviewer 是只讀的審查 agent。
- **U1、U2、U3**：stage B 的一條鏈（U1 Core、U2 Host、U3 Polar2 設定與 Integration），同一個 implementer 依序做，worktree `../_wt_19-process`，base `524527e`。

### 2.2 U1 Core：執行器（新檔 `src/AdsPlcSimulator.Core/PackML/Behavior/ProcessRules.cs`，`internal`）

```csharp
internal sealed class ProcessRules
{
    /// <exception cref="ServiceHostException">A path does not resolve (same message as ModuleRules.Resolve).</exception>
    public static ProcessRules Create(SymbolTable symbols, string modulePath, string paramPath, ProcessBehavior behavior);

    /// <summary>Count, then each step 1..count with the checks in list order, then cycle pairing. First failure wins.</summary>
    public EntryCheck Check(ProcessImage image);

    /// <summary>Copies the step plan (count, each step's time, cycle control and cycle count) and starts at step 1: writes its SVIDs; the step began at now. dryRun is kept for the whole run.</summary>
    public ProcessRun Start(ProcessImage image, TimeSpan now, bool dryRun);
}

internal sealed class ProcessRun
{
    /// <summary>Moves past every step whose time has passed (several in one scan when they are short). True when the last step has ended; the non-Keep SVIDs of the last step are then written 0.</summary>
    public bool Advance(ProcessImage image, TimeSpan now);

    /// <summary>Writes 0 to the non-Keep SVIDs of the current step (nothing after the run has finished).</summary>
    public void Leave(ProcessImage image);

    /// <summary>Unhold or Unsuspend: the current step starts again at now and its SVIDs are written again.</summary>
    public void Resume(ProcessImage image, TimeSpan now);
}
```

規則：
- **解析**：`Create` 把每個含 `[i]` 的路徑以 i = 1..MaxCount 取代並解析（`ModuleRules.Resolve`），不含 `[i]` 的解析一次。所有路徑以 `$"{paramPath}.{path}"` 解析（`paramPath` = `$"{modulePath}.ServiceParam.{relativeService}"`）；SVID／ECID 路徑以 `$"{modulePath}.{target}"` 解析。
- **解析後的形狀**（`ProcessRules` 的 private 成員）：
  ```csharp
  private sealed record StepPath(SymbolRef[] ByStep);                 // index 0 = step 1; one entry when the path has no [i]
  private sealed record Choice<T>(StepPath[] Keys, IReadOnlyDictionary<string, T> Choices);
  private sealed record ResolvedCheck(ProcessCheck Check, StepPath Field, SymbolRef? MaxField, Choice<double>? MaxBy, StepPath? WhenField);
  private sealed record ResolvedWrite(ProcessWrite Write, Choice<(SymbolRef Target, bool IsReal)> Target, StepPath? ValueField, Choice<SymbolRef>? Ecid, StepPath? WhenField, StepPath? NegateField);
  ```
  `StepPath.At(int step)` 回 `ByStep[step - 1]`，沒有 `[i]` 時回 `ByStep[0]`。
- **讀值**：數字與 TIME 欄位用 `PlcValue.ToDouble`（TIME → 毫秒）；條件、key、循環控制與次數用 `PlcValue.ToInt64`；ECID 文字用 `ServiceRules.ParseNumber`（非數字 → 0，#16 R8）。enum 欄位由 `ValueCodec` 解成底層整數（`ValueCodec.cs:18`），兩個函式都能讀。
- **共用 helper**：`ServiceRules` 的 `ParamOutOfRangeId`、`UnrepresentableSourceId`、`SourceErrorId(double)`、`Text(double)`、`ParseNumber(string)`、`Format(bool isReal, double number)` 改成 `internal`（const 與 static），`ProcessRules` 直接使用，不複製。`Format` 對非有限值回 `"0"`／`"0.0"`（以 0 格式化）；DINT 四捨五入是 `MidpointRounding.AwayFromZero`（2.5 → 3、−2.5 → −3），夾在 int 範圍。寫入一律 `image.WriteValue(target, text, WriteSource.Workflow)`（同 `ServiceRules.WriteAll`）。
- **Check 順序與訊息**（MainErrorId 1）：
  1. count 不在 1..MaxCount：SourceErrorId = `unchecked((uint)count)`、Message `{CountField} out of range (1~{MaxCount}).`。
  2. 每步 i = 1..count，checks 依清單順序；`When` 不成立則略過。路徑顯示為把 `[i]` 換成 `[{i}]`（例 `ProcessSteps[3].ArmIndex`）：
     - Range：上限 = `Max.Constant`，或 `Max.Field` 的值（`ToDouble`），或 `Max.Lookup` 以 key 查到的值（查不到 → 上限 = Min − 1，必定失敗）。`!(value >= Min && value <= max)` 時失敗：SourceErrorId = `SourceErrorId(value)`（同 #17：有限值取整數部分 `unchecked`，非有限 → 4294967295）、Message `{path} out of range ({Text(Min)}~{Text(max)}).`（`Text` 同 #17，invariant）。
     - GreaterThan：`!(value > Min)` 時失敗：SourceErrorId 同上、Message `{path} must be greater than {Text(Min)}.`。
  3. 循環配對（`Cycle` 不是 null 時）：依步驟順序，控制值 = StartValue 推入步驟編號、= EndValue 時若堆疊空 → 失敗：SourceErrorId = 該步編號、Message `{ControlPath} End without Start.`；結束時堆疊非空 → 失敗：SourceErrorId = 堆疊頂端（最內層未關閉）的步驟編號、Message `{ControlPath} Start without End.`（`{ControlPath}` 為該步的顯示路徑）。
- **執行**：
  - `ProcessRun` 由 `ProcessRules.Start` 以 `internal` 建構子建立，持有 `ProcessRules` 的參考。
  - 快照（`Start` 時讀一次，之後不再讀）：`_count`；每步 1..count 的 `_time[s]`（毫秒，小於 1 時當成 1，所以一次 `Advance` 最多推進「經過的毫秒數」步）、`_control[s]`、`_cycleCount[s]`。client 在 Execute 中改這些欄位不影響這次 run（PLC 的步驟 FB 也是 Start 時複製 recipe）。寫入的值（Setpoint、RotateSpeed、條件、key、ECID）在進入該步時才讀。
  - 狀態：`_dryRun`（Start 時保存）、`_step`（1-based）、`_stepStarted`、`_cycles`（堆疊，元素為 `(int StartStep, long Remaining)`）、`_written`（目前步驟寫過的非 Keep SVID 目標）、`_finished`。
  - CycleCount 是整段（Start 到 End，含兩端）的執行次數，含第一次。
  - 進入步驟 s（含第 1 步）：先把 `_written` 中的目標寫 0（`Format` 依 `IsReal`）並清空；控制值 = StartValue 且（堆疊空或頂端 StartStep ≠ s）時推入 `(s, CycleCount)`；然後依 writes 清單寫入：`When` 不成立略過；Target 以 key 查（查不到略過）；值 = DryRunZero 且 dryRun 時 0，否則 Field 讀值或 Ecid 查到的 ECID 文字 → `ParseNumber`；`NegateWhen` 成立且值 ≠ 0 時取負；以 `ServiceRules` 的 `Format`（REAL → `FormatFloat32`；DINT → 四捨五入夾在 int 範圍）寫入；非 Keep 的目標加入 `_written`。
  - 步驟 j 結束時的下一步：控制值 = EndValue 時，頂端 `Remaining − 1`；仍 > 0 → 下一步 = 頂端 StartStep；否則彈出，下一步 = j + 1。其他情況下一步 = j + 1。下一步 > count → 結束：`_written` 寫 0、`_finished = true`。
  - `Advance`：`while (!_finished && now - _stepStarted >= _time[_step])`：`_stepStarted += _time[_step]`，前往下一步。回傳 `_finished`。
  - `Leave`：未結束時把 `_written` 寫 0 並清空；結束後不寫。
  - `Resume`：未結束時 `_stepStarted = now`，重寫目前步驟的 SVID（同「進入步驟」，用 `_dryRun`，但不推入循環）。
  - 循環範例（AC10）：2 Start×3、4 Start×3、5 End、6 End → 1, 2, 3, 4, 5, 4, 5, 4, 5, 6, 2, 3, 4, 5, …（共 1 + 3×(2 + 3×2 + 1) 步）。

### 2.3 U1 Core：`ServiceRules` 與 `ServiceHost` 變更

`ServiceRules`（`ExecuteEntryRules.cs`）：
- 新欄位 `private readonly ProcessRules? _process`；`Create` 在 `behavior.Process` 不是 null 時建立（`paramPath` 即現有的 `param`）。
- `CheckParams`：現有 ranges 與 duration 檢查之後，`_process?.Check(image) ?? EntryCheck.Pass`（寫成兩行 if，避免 `?.` 加 `??` 的分支）。
- 新方法 `public ProcessRun? StartProcess(ProcessImage image, TimeSpan now, bool dryRun) => _process?.Start(image, now, dryRun);`
- 共用 helper 改 `internal`（見 §2.2「共用 helper」）；`Format` 的參數改成 `(bool isReal, double number)`（現有呼叫傳 `write.Write.IsReal`）。

`ServiceHost.ServiceUnit`：新屬性 `public ProcessRun? Process { get; set; }`；`BeginExecuteEntry` 設 `Process = null`。

`ServiceHost.cs`：
- `EnterExecute`：fresh entry 通過檢查、`token is null` 且 `service.ConfigParams is null` 時，在 `WriteOnEnter` 之後 `service.Process = service.Rules.StartProcess(image, now, dryRun);`（`dryRun` 是 `CheckEntry` 的 out 值，已存入 `service.EntryDryRun`）。有 `ConfigParams` 的 service（SetConfig）不執行步驟：它在下一次 scan 就完成。非 fresh（Unhold／Unsuspend）且 `token is null` 時，在 `WriteOnEnter` 之後 `service.Process?.Resume(image, now);`。
- `IsServiceActingStateDone` 的順序不變：Starting → 非 Execute → `ExecuteRejected` → 被接管（`TakeCompletion`）→ 其餘。「其餘」抽成 `private bool IsExecuteDone(ServiceUnit service, ProcessImage image, TimeSpan now)`：`ConfigParams` 不是 null → true；`service.Process` 不是 null → `service.Process.Advance(image, now)`；否則 `IsNaturalDelayElapsed`。done 時照舊 `WriteBeforeComplete`。被接管的 service 在前一步就 return，`Process` 也是 null。有 process 的 service 不看 CompletionBehavior（process 決定 Execute 時間）。
- `LeaveExecute`：`ExecuteRejected` 或被接管時照舊 return；否則先 `service.Process?.Leave(image)`，再 `WriteOnLeave`。
- 被接管（token 不是 null）時不呼叫 `StartProcess`，所以不執行步驟（AC16）；被拒絕時也不呼叫。
- 狀態清除（AC15）：下一次 fresh entry 的 `BeginExecuteEntry` 設 null；Stop、Abort 後不經 Starting 不會回到 Execute，所以舊的 run 不會再被推進；`Reset` 已呼叫 `BeginExecuteEntry`。

JSON key 為 camelCase（`count`、`maxCount`、`time`、`cycle`、`checks`、`writes`、`field`、`min`、`max`、`maxField`、`maxBy`、`greaterThan`、`when`、`svid`、`svidBy`、`value`、`dryRunZero`、`keep`、`ecid`、`ecidBy`、`negateWhen`、`key`、`values`、`control`、`start`、`end`、`equals`）；`UnmappedMemberHandling.Disallow` 照舊。`Equals` 屬性名與 `object.Equals` 衝突：C# 屬性名用 `EqualsValue`，加 `[JsonPropertyName("equals")]`。

  - `{0}: exactly one of max, maxField and maxBy is required.`（沒有 `greaterThan` 時）
