# #7 Proposal：Polar2 SVID、ECID 內容補入

Issue：https://github.com/KaiJuY/ADS_PLCSimulator/issues/7（AC 1–14 以 issue 為準，§4 逐條對照）。

## 0. 名詞與現況

| 名詞 | 意思 |

1. `Polar2_ModuleModeInit` workflow（`trigger.onStart`）寫入 slot 1 的 `ModuleStatus.ModuleId`=1、`Enabled`=TRUE、`ModuleType`='Polar2'（#3），再對 slot 1..6 迴圈寫 `ModuleVariableList[1]` 的 Id=1、Name='Module Mode'、DataType=Integer_32bit、Value='1' 與 `Variable.PublishedCount`=1（#1）。

## 2. 形狀

### 2.1 腳本（U1，Create `projects/Polar2Chamber/spec/spec-to-config.py`，Python 3 標準函式庫，不需套件）

```
python spec-to-config.py "<規格書.xlsx>" "<輸出 module-config.json>"
```

- 以 `zipfile` + 正規式讀 xlsx：工作表名稱經 `xl/workbook.xml` 的 `<sheet name r:id>` 與 `xl/_rels/workbook.xml.rels` 的 `Target` 對到 `xl/worksheets/sheetN.xml`；儲存格欄位一律取自 `r` 屬性的欄字母（缺少的儲存格視為空字串，不依位置）；`t="s"` 取 `xl/sharedStrings.xml` 第 n 個 `<si>` 內所有 `<t>` 串接（含 rich text `<r><t>`）；`t="inlineStr"` 取 `<is>` 內的 `<t>`；其他取 `<v>` 原文；全部做 XML entity 解碼（`html.unescape`）。
- 讀 `Object Quantity`（第 1 列標題；A = 物件名、B = 數量）、`ModuleVariableList_SVID`、`ModuleConfigParamList_ECID`（第 1 列標題；B = 群組、C = 項目名、D = 型別、E = 單位）。群組、項目名、型別、單位都去頭尾空白（規格書有 `Lift Timeout `、`FFU ` 這類尾端空白）。
- **群組**：B 欄非空時更新目前群組（去頭尾空白）；C 欄空的列跳過。
- **展開**：
  - 群組為空字串或 `-`：名稱 = 項目名。
  - 群組以 `_X` 結尾：base = 去掉 `_X` 再去頭尾空白；數量 = `Object Quantity` 中名稱去空白後與 base 去空白後相同（不分大小寫）的數量；找不到 → 失敗。名稱 = `<base 去空白><序號> <項目名>`（例 `Arm1 Lift Speed (Normal)`、`FixNozzle2 Flow/Pressure`、`ExhaustFan3 Pressure`）。序號 1..數量，外層迴圈是序號、內層是該群組的項目（即 Arm1 全部項目，再 Arm2 …）。
  - Arm 的 nozzle 數：Arm1 3、Arm2 3、Arm3 2、Arm4 1（腳本內固定；來源是規格書 ECID 表 `Nozzle1 Flow Offset` 列的註解「二代Chamber Arm1,2 有 Nozzle *3；Arm3 有 Nozzle *2；Arm4 有 Nozzle *1」，Allen R3 確認）。base 為 `Arm` 時，項目名第一個 `No(z|zzle)(\d)` 的數字大於該 Arm 的 nozzle 數 → 不產生該筆。
  - 其他群組：名稱 = `<群組> <項目名>`（例 `Outside Ring Rotate Speed`、`Holder Rotate Speed`）。
- **型別**：`Integer_32bit`→`DINT`、`Float_32bit`→`REAL`、`Boolean`→`BOOL`、`String(80)`→`STRING`；其他 → 失敗。
- **ASCII**：名稱、單位非 ASCII → 失敗。
- **縮寫**（名稱 > 30 byte 時依序套用；每條規則取代該名稱中所有出現處、區分大小寫；每套用一條就檢查一次，≤ 30 即停止）：`Chemical`→`Chem`、`Related`→`Rel`、`ServiceId`→`SvcId`、`ToFacility`→`ToFac`、`Drainer`→`Drn`、`Nozzle`→`Noz`、`Position`→`Pos`、`Temperature`→`Temp`、`Pressure`→`Pres`、`Enable`→`En`、`Count`→`Cnt`、`Supply`→`Sup`、`Exhaust`→`Exh`、`Speed`→`Spd`、`Timeout`→`TO`、`Limit`→`Lim`。單位 > 10 byte 時套用 `ml/sec`→`ml/s`。仍超過 → 失敗。有縮寫時該筆加 `"comment": "<原名稱>"` 或 `"comment": "unit: <原單位>"`（兩者都有時以 `; ` 連接）。
- **ID**：SVID、ECID 各自依輸出順序從 1 編號。名稱在各自清單內重複 → 失敗。
- **輸出**（UTF-8、LF、`indent=2`、`ensure_ascii=False`，鍵順序固定）：

```json
{
  "schemaVersion": 4,
  "modules": [
    {
      "enabled": true,
      "moduleType": "Polar2",
      "slot": 1,
      "id": 1,
      "variableList": [ { "id": 1, "name": "Module Mode", "unit": "", "dataType": "DINT" } ],
      "configParamList": [ { "id": 1, "name": "Module Disable", "unit": "", "dataType": "BOOL" } ]
    }
  ]
}
```

- 失敗時印出原因（表名、列號、名稱）並以 exit code 1 結束，不寫輸出檔。
- 本 proposal 撰寫時以原型腳本（session 暫存，未進 repo）試算，correctness reviewer 另以獨立模擬重算：SVID 63 筆、ECID 438 筆、81 個 ECID 名稱需縮寫、縮寫後全 ≤ 30 byte、無重複。**數字以實作腳本的輸出為準**，由 §6 ModuleConfigTests #6 驗證。

### 2.3 Host：設定檔模型與發布（U2，Create `src/AdsPlcSimulator.Host/Project/ModuleConfig.cs`）

```csharp
public sealed class ModuleConfigException(string message) : Exception(message);

// 以 init 屬性與預設值宣告，JSON 缺欄位時得到預設值而不是 null。
internal sealed record ModuleConfigFile
{
    public int SchemaVersion { get; init; }
    public List<ModuleConfigEntry?>? Modules { get; init; }
}

internal sealed record ModuleConfigEntry
{
    public bool Enabled { get; init; }
    public string? ModuleType { get; init; }
    public int Slot { get; init; }
    public uint Id { get; init; }
    public List<DescriptorConfig?>? VariableList { get; init; } = [];
    public List<DescriptorConfig?>? ConfigParamList { get; init; } = [];
}

internal sealed record DescriptorConfig
{
    public uint Id { get; init; }
    public string? Name { get; init; }
    public string? Unit { get; init; }
    public string? DataType { get; init; }
}

/// <summary>Publishes module identity, SVIDs and ECIDs from a project's config/module-config.json into the process image.</summary>
internal static class ModuleConfigPublisher
{
    public const string RelativePath = "config/module-config.json";
    internal const string ModulesRoot = "GVL_Module.Chamber_Control";

    /// <returns>The config path when published; null when the project has no config file.</returns>
    public static string? PublishIfPresent(string projectDirectory, SymbolTable symbols, ProcessImage image);

    internal static ModuleConfigFile Parse(string json, string path);                  // JSON 與檔案本身的檢查
    internal static void Publish(ModuleConfigFile config, string path, SymbolTable symbols, ProcessImage image); // 依 symbol 表檢查後才寫入
}
```

**Parse**（`System.Text.Json`，`JsonSerializerDefaults.Web`，未知欄位忽略；欄位缺少時用預設：`enabled` false、`moduleType` null、`variableList`／`configParamList` 空）。錯誤丟 `ModuleConfigException("<path>: <原因>")`：
- JSON 無效（`JsonException` 訊息）。
- `schemaVersion` 不是 4。
- `modules` 缺少、為 null 或不是陣列；`modules` 內有 null 元素；`variableList`／`configParamList` 為 JSON null 或內有 null 元素（欄位缺少時為空清單，不是錯誤）。
- 同一 `slot` 出現兩次。
- 同一 module 的 `variableList` 或 `configParamList` 內 `id` 重複，或 `id` 為 0。
- `dataType` 不是 `DINT`、`REAL`、`BOOL`、`STRING`。
- `name`、`unit`、`dataType` 缺少或為 null。
- `name`、`unit`、`moduleType` 含非 ASCII 字元（PLC 以 Latin-1 編碼，非 ASCII 會被換成 `?`，所以拒絕）。

**Publish** 分兩個階段：(1) 檢查階段：對全部 enabled module 解析所有要寫的 symbol 路徑（`symbols.TryResolve`，失敗即錯誤）、做下列檢查，產生寫入計畫 `List<(SymbolRef Symbol, object Value)>`；(2) 寫入階段：只對計畫逐筆 `image.WriteValue`。檢查階段有任何錯誤就不寫任何東西。錯誤丟 `ModuleConfigException("<path>: <原因>")`：
- `ModulesRoot` 解析失敗或不是一維陣列。
- `slot` 不在該陣列的上下界內（`ArrayType.Dimensions[0].LowerBound`／`UpperBound`）。清單 index 也從各清單陣列的 `LowerBound` 起算（Polar2 為 1）。
- 清單筆數超過 `ModulesRoot[slot].ModuleVariableList`／`.ModuleConfigParamList` 陣列的 `ElementCount`（上限取自 symbol 表，不寫死）。
- `name`、`unit`、`moduleType` 的長度（皆為 ASCII，字元數 = byte 數）超過對應 `StringType.Length`（`Name` 30、`Unit` 10、`ModuleType` 16，從 symbol 表取得）。

寫入計畫的內容（寫入時 `image.WriteValue(symbol, value, WriteSource.Workflow)`；此時 `FlowRuntime` 尚未建立，沒有觸發器在監聽，來源不影響行為）：
- `ModuleStatus.ModuleId` = `id`、`ModuleStatus.Enabled` = TRUE、`ModuleStatus.ModuleType` = `moduleType ?? ""`。
- `ModuleVariableList[i]`（i 從 1，依檔案順序）：`Id`、`Name`、`DataType`（`DINT`→`Integer_32bit`、`REAL`→`Float_32bit`、`BOOL`→`Boolean`、`STRING`→`String_80byte`，以成員名稱字串寫入）、`Unit`、`Value`（`DINT`／`REAL` → `"0"`、`BOOL` → `"FALSE"`、`STRING` → `""`）；`ModuleStatus.Variable.PublishedCount` = 筆數。
- `ModuleConfigParamList[i]`：同上五欄，加 `IsBound` = TRUE、`HasLimits` = FALSE（`LowerLimit`／`UpperLimit` 保持 0）。
- `enabled` 為 false 的 module 不寫入。

## 8. 考慮過的做法

issue #7「考慮過的做法」全部不採用（理由見 issue）。另外：
- **發布放在 Core（`PlcProgram`）**：不採用。設定檔是專案層級的 Host 概念；Core 不認識 `config/` 與 framework 的 module 結構。
- **發布在 `FlowRuntime` 建立之後、用 `WriteSource.Client`**：不採用。會觸發 On Client Write／On Change 的 workflow；放在 `FlowRuntime` 之前就沒有監聽者。
- **新增 `WriteSource.Config`**：不採用。目前沒有任何寫入來源判斷需要區分它；在 `FlowRuntime` 之前寫入時來源不影響行為。
- **腳本用 C#**：不採用。產生方式在 issue 中定為暫定（Allen：先不要定下來）；Python 標準函式庫即可讀 xlsx，不進入 solution build。

## 9. 不在範圍

issue #7「不在範圍」全部沿用。另外：腳本的單元測試（以 ModuleConfigTests #6 驗證產物代替）；`.adf/proposals/1.md`、`.adf/scenarios/1.md` 中的舊配置數字（歷史紀錄）。

## 10. 風險

- **與真 PLC 配置不同**：上限改 500 後，模擬器 `Chamber_Control` 大小與 offset 和 854 不同。用 symbol 名稱綁定的 client（AdsClientForPolarII、Integration driver）不受影響；以固定 offset 存取的工具會讀錯位置。
- **framework 重新複製**：若照 README 重新複製 `plc/Framework/` 而漏掉重新套用 500，Host 的上限（取自 symbol 表）會變回 300，Polar2 的設定檔 438 筆 → Run 失敗並指出原因（不會靜默截斷）。
- **暫定 ID 會變**：規格書加入或刪除列時，腳本重編後的 ID 可能全部位移；Handler 若存了 ID，需改用新的設定檔內容。
- **slot 2–6 的 `Module Mode` Value**：`Polar2_Chamber_Initial`、`Polar2_Chamber_SetMode` 仍對 `ModuleVariableList[#].Value` 寫入（依 service 所在 slot）。slot 2–6 沒有發布 SVID，寫入落在未發布的項目（`PublishedCount` 0），client 不會讀它；無功能影響。
- **Polar2 沒有設定檔**：移除 workflow 的 identity 節點後，若刪掉 `config/module-config.json`，slot 1 的 identity 與 SVID 都不會發布（只有 Information log）。設定檔在 repo 中，不會發生在正常使用。
- **Run 時間**：發布約 63 × 6 + 438 × 8 次寫入（< 4000 次），可忽略。
