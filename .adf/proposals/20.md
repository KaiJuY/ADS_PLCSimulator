# #20 Proposal：Editor 模組依賴整理

## 1. Goal
#20（https://github.com/KaiJuY/ADS_PLCSimulator/issues/20）：把 `setDirty`／`setSaveState`、`suggestSymbols`、座標函式搬到被依賴的一側，讓沒有模組 import 進入點 `editor.js`，並消掉 `canvas`↔`palette`、`canvas`↔`render` 兩組循環 import。行為不變。

Issue 驗收條件（簡述）：
- AC1：`setDirty`、`setSaveState` 搬到 `state.js` 並 export；沒有模組 import `editor.js`。
- AC2：`suggestSymbols`、`symbolTimer` 搬到 `variable.js`；`variable.js` 不 import `render.js`。
- AC3：新增 `view.js`（`applyView`、`screenToWorld`、`isBackground`，只 import `state.js`）；`palette.js`、`render.js` 不 import `canvas.js`。
- AC4：只搬移，函式內容與名稱不變。
- AC5：ESLint、load-graph、CDP 比對 main 與新版（#11 的 9 步加 3 步）。

背景：Editor 是 `src/AdsPlcSimulator.Host/wwwroot/editor/` 下的 ES module 圖，進入點是 `index.html:81` 的 `<script type="module" src="editor.js">`。#11 把它拆成 10 個檔（`.adf/proposals/11.md`）。ADF 階段：F 實作、G 清理、H gate 與 reviewer、I 以使用者操作驗證（`C:\Users\AllenY\.claude\plugins\cache\adf\adf\0.2.4\references\flow.md`）。

## 4. Behavior
- 求值順序（從 `editor.js` 深度優先，循環中已在處理的模組略過）：
  - main：`api`、`project`、`state`、`variable`、`live`、`palette`、`canvas`、`render`、`model`、`editor`。
  - 新版：`api`、`project`、`state`、`variable`、`live`、`view`、`render`、`model`、`palette`、`canvas`、`editor`。
  - 差異：`palette`、`canvas` 從 `render` 之前移到 `model` 之後。頂層程式只註冊事件；同一元素上的事件種類不重疊（`canvas.js`：`#canvas` 的 `pointerdown`、`wheel`、`pointermove`；`palette.js`：`#canvas` 的 `dragover`、`drop`、`dblclick`、`contextmenu`；`editor.js`：`window` 與工具列），所以註冊順序改變不影響事件的觸發順序。`render`、`model` 的頂層沒有呼叫 `palette`、`canvas` 的函式。
- `state.js`、`view.js` 只 import `api.js`／`state.js`，是葉節點。`setDirty`、`setSaveState`、`suggestSymbols`、`applyView`、`screenToWorld`、`isBackground` 都是 function 宣告，只在事件處理或函式內被呼叫，沒有模組在頂層呼叫它們（`variable.js:24-29` 的頂層程式只註冊事件）。#11 AC4 的循環規則仍成立。
- AC1：`editor.js` 不再被任何模組 import；`setDirty` 的呼叫者（`canvas`、`live`、`model`、`render`、`editor`）都從 `state.js` 取。
- AC2：`render.js:142-143` 的 Symbol 參數輸入框與 `variable.js` 的 `#variablePath` 都呼叫 `variable.js` 的同一個 `suggestSymbols`，共用同一個 `symbolTimer`（與現在相同：現在兩者共用 `render.js` 的那個）。
- AC3：`render.js` 的 `renderAll` 呼叫 `applyView`、`portCenter` 呼叫 `screenToWorld`，改由 `view.js` 提供。`canvas.js` 不再被其他模組 import，改由 `editor.js` 以 `import './canvas.js'` 載入。
- 搬移後的依賴：`editor.js` 入度 0；`canvas`↔`palette`、`canvas`↔`render` 消失；`variable`→`render` 消失，新增 `render`→`variable`。仍有的循環：`model`↔`render`、`render`↔`live`、`live`↔`variable`、`render`→`variable`→`live`→`render`（issue 不在範圍）。

## 8. Alternatives
- 消除全部循環 import：不採用；剩下的要搬 `renderAll`、`decorateNode` 等核心函式（grill Q1）。
- `setDirty` 放新檔 `saveState.js`：不採用；2 個函式不值得一個檔（grill Q2）。
- `suggestSymbols` 留在 `render.js`：不採用；symbol 查詢屬於 variable 段。代價是 `render.js` 多一條 import `variable.js`，循環數不變（grill Q3）。
- 座標函式留在 `canvas.js`：不採用；它們是 `canvas`↔`palette`、`canvas`↔`render` 循環的唯一原因（grill Q4）。
- 只沿用 `cdp11.mjs`：不採用；它沒走到 3 條被搬動的路徑（grill Q6）。

「grill Qn」是 issue #20 的「決策紀錄」中 Allen 的回答；理由寫在上面每一行。
