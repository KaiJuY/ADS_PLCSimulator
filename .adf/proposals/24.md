# #24 Proposal：Polar2 Simulation 頁 v2（外形修正、Shutter／SideVent／Damper／Gripper、Jog、甩液）

Issue：https://github.com/KaiJuY/ADS_PLCSimulator/issues/24（決策 Q1–Q22 記在 issue 的「決策紀錄」）。

## 1. 目標

讓 Polar2 的 63 個機構 service 在 Simulation 頁有動作，並把頁面外形改成真機配置：移除 FFU；加上 SideVent 與下方風扇、Damper、牆上的 Fixed Nozzle、4 個 Port 杯、真空吸盤與夾爪；再加上甩液效果。

不改 C# 產品程式碼（`src/**`）。只改 C# 測試（`tests/**`）。

決定與理由：
- ECID 16／94／172／234 是 `module-config.json` 的「ArmN Rotate Speed (Jog)」（RPM），也是 `service-behaviors.json:267-268,284-285,301-302,312-313` 的 SVID 寫入來源。270／282／294／306 是「CupN Speed (Jog)」（mm/s）。
- `JogPositive`／`JogNegative` 沒有 `beforeComplete`（ExecuteUntilExternalStop，不會自己完成）。IncrementalJog 的 `beforeComplete` 送 `StepDone`，不再送 `IncrementalJog`：相對移動再送一次會多走一步；`StepDone` 讓頁面對齊這一步的目標並結束這一步，不依賴頁面與 Host 的計時剛好相同（§4 AC6.2）。
- OPR 的 `leave` 送 `Hold`：Stop 或 Abort 中途的 OPR 讓 Holder 停在當下角度（§4 AC5.2）。正常完成時 `beforeComplete` 已對齊到 0°，`Hold` 不改變畫面。`Hold` 不存進 `simState`，重新整理時以最後的 `Home` 顯示 0°。`Home` 存在 `simState`，重新整理時停在 0°。
- 既有的 Jog 項目（`Arm[n].Rotate.*Jog*`、`Cup[n].Lift.IncrementalJog`）只加 `sim`，既有的 `onEnter`、`beforeComplete`、`onLeave` 不動。其餘是新項目，只有 `sim`（其他清單預設為空，`src/AdsPlcSimulator.Host/Project/ServiceBehaviorConfig.cs:36-47`）。
- 不設 `dryRunAction`：DryRun 時機構照常動畫（issue AC9）。

`tween` 擴充為 `{ from, to, start, dur, rate, min, max }`；`rate` 預設 0。`rate !== 0` 時為等速模式：
- `valueAt` = clamp(`from` + `rate` × (now − start) / 1000, `min`, `max`)。
- `settled` 回傳 false（Jog 期間 `busy` 為 true，即使已到邊界，直到 `Hold`）。
- `moveTo`（含 goal 為 null 的凍結）先取 `valueAt` 的當下值，再把 `rate` 設回 0。

`apply(command, now, replay)` 加第三個參數：`simState` 分支傳 true，`sim` 分支傳 false（`runtime.js:217-218`）。

`apply()` 的標籤改由每個 type 的 `labelOf(entry, action, value)` 決定（取代 `runtime.js:92-94` 的共用寫法）：

| type | `labelOf` 回傳 |
|---|---|
| rotate、cup、lift | `formatLabel(value, ACTION_UNITS[type]?.[action] ?? UNITS[type])`；value 為空時回傳 `undefined` |
| spin | `CW`／`CCW`：`formatLabel(value, "RPM")`；`Stop`、`Home`：`null` |
| gripper、ringLift、shutter、vent、damper | action 名稱 |
| drain | `"Drain " + action.slice(-1)` |
| nozzle、port、fixed、exhaust | `formatLabel(value, UNITS[type])`；`Off` 為 `null` |

`labelOf` 回傳 `undefined` 時不寫 `state.labels`，回傳 `null` 時清空，其他字串寫入。`Hold` 一律不改標籤。

Jog 的啟動函式：`jogFrom(t, rate, min, max, now)`：`from = valueAt(t, now)`、`start = now`、`dur = 0`，並設 `rate`、`min`、`max`。rotate 與 cup 的 handler 依 action 分支：`JogPositive` 傳 +速率，`JogNegative` 傳 −速率；範圍見 AC6.1。`valueAt` 先檢查 `rate !== 0`，再檢查 `settled`（`runtime.js:11-12` 在 `dur <= 0` 時直接回傳 `to`）。

## 3. 資料與狀態

- Config（`service-behaviors.json`）：Host 載入時讀取，Run 期間不變。
- `simState`：`LiveHub` 持有，Host 的 scan 執行緒寫入，WebSocket 連線時讀取。本 issue 不改。
- 頁面狀態：`runtime.js` 的 `state`，只在瀏覽器主執行緒，由 `onMessage` 與 `draw` 讀寫。`project` 訊息重設為 `freshState()`，並記下 `projectName = data.running ? data.name : null`。
- `localStorage`：
  - key：`STORAGE_PREFIX + projectName + ":" + target key`（target key 是 `TARGETS` 裡的 key，例如 `Arm1.Rotate`、`Cup1.Master`）。`projectName` 為 null 或空字串時不讀也不寫。
  - 值：數字字串（Arm 角度 deg，與 `state.rotate` 同單位；Cup 高度 mm，與 `state.cups` 同單位）。
  - 寫入：收到 `Hold` 且 `lastAction[target]` 是 Jog 類時，寫入凍結後的值。
  - 讀取：`replay` 為 true 且指令 action 是 Jog 類時。讀到的值先 clamp 到該 target 的範圍。
  - 刪除：該 target 收到 Jog 類以外、非 `Hold` 的 action 時（例如 `Top`、`NozzlePort`），刪除它的 key，避免之後重播讀到更早的位置。
  - 每次存取包在 `try/catch`；失敗視為沒有存值。

## 4. 行為

### AC1 外形
1. 不再畫 FFU 與 4 根排氣管。外罩牆與箱體牆都用 `WALL_OPACITY` 半透明，所以背面的 SideVent 3、4 與箱體內 4 個風扇都看得到。

### AC5 Holder 與 OutsideRing
1. `Holder.Gripper` `Open`／`Close`：`gripper` tween 到 0／1。
2. `Holder` `Home`：
   - `a` = 目前畫面角度（`home` 不為 null 時是 `valueAt(home, now)`，否則是 `spinAngle(now)`，未取模）；`dir = 0`；`angle = a`；`since = now`；`home = { from: a, to: 2π × round(a / 2π), start: now, dur: durationMs }`（最短路徑到最近的 2π 倍數，與先前方向無關）。
   - `durationMs` 為 0 時 `home.dur = 0`，`valueAt(home)` 直接是 `to`。enter 與 beforeComplete 的終點相同。
   - Holder 的畫面角度：`home` 不為 null 時用 `valueAt(home, now)`，否則用 `spinAngle`。
   - `CW`／`CCW`／`Stop`／`Hold`：先把 `angle` 設為目前畫面角度、`since = now`，再把 `home` 設為 null。`Hold` 不改 `dir`（OPR 期間為 0）；`CW`／`CCW`／`Stop` 照既有規則設 `dir`。
   - 所以連續兩次 `Home`，或 Unhold 重送的 `Home`，都從目前畫面角度開始，不會跳回舊角度。
3. `Holder` `CW`／`CCW`：`rpm = Number(value)`，無效時 0。`Stop`、`Home`：`rpm = 0`。
4. `OutsideRing.Lift` `Top`／`Down`：`ringLift` tween；OutsideRing 的 z 加上 `valueAt(ringLift)`。

### AC6 Jog
1. `JogPositive`／`JogNegative`：從目前值開始等速移動。速率：Arm ±`JOG.rotateDegPerS`，Cup ±`JOG.cupMmPerS`。範圍：Arm 為 `ARM_ROTATE_DEG` 所有值的最小、最大（−48°、35°）；Cup i 為 `CUP_RIM.Down[i]` 到 `CUP_RIM.Top[i]`。到邊界停在邊界。正方向：Arm 為角度增加，Cup 為上升（假設：PLC 與 config 都沒有寫明 Cup Lift 的正方向；與 Arm 一致取「值增加」）。
2. `IncrementalJog`：
   - `step = sign(Number(value))`；`step` 為 0 或 value 無效時不動，也不建立 `stepGoal`。
   - 若 `stepGoal[target]` 存在，而且 `sign(stepGoal − 目前值)` 等於 `step` 或為 0（同方向的未完成步，或動畫已到目標但 `StepDone` 還沒到），目標沿用 `stepGoal[target]`；否則目標 = clamp（目前值 + step × `JOG.rotateStepDeg` 或 `JOG.cupStepMm`），存入 `stepGoal[target]`。
   - 以 `durationMs` 補間到目標。
   - `StepDone`（`beforeComplete`，durationMs 0）：若 `stepGoal[target]` 存在，直接設為該值並刪除；不存在時不動。
   - 該 target 收到 `IncrementalJog`、`StepDone`、`Hold` 以外的 action 時（含 `JogPositive`／`JogNegative`），刪除 `stepGoal[target]`。刪除只在 `apply()` 發生，不依賴 `draw`，頁面隱藏時也正確。
3. Unhold：Hold 再 Unhold 時 `ServiceHost` 重送 `enter`（`ServiceHost.cs:505-514`），頁面沿用同一個目標，不會多走一步；剩下的距離以完整的 `durationMs` 走完（畫面速度變慢）。正常完成時由 `StepDone` 對齊，不受 Host 與頁面的計時差影響。已知限制：IncrementalJog 被 Stop 或 Abort（沒有 `StepDone`）後，下一次同方向的 IncrementalJog 會先走完上次的目標，而不是從當下位置再走一步。
4. `Hold`（Jog 的 `leave`、`DecoupleStop` 的 `enter`）：凍結在當下值。若 `lastAction[target]` 是 Jog 類，寫入 `localStorage`。
5. `replay` 為 true 且 action 是 Jog 類（IncrementalJog 完成後最後一筆是 `StepDone`）：不移動、不建立 `stepGoal`；讀 `localStorage`，有值就直接設為該值，沒有值就留在初始位置。不寫錯誤列。
6. 標籤：顯示 value，單位為 `ACTION_UNITS[type][action] ?? UNITS[type]`。

### AC7 Drain 標籤
`SelectK`：`state.labels[target] = "Drain " + K`（K 取自 action 名稱的最後一個字元）。沒有 `leave`，標籤一直保留到下一個 `SelectK` 或 `project` 重設。`simState` 重播時照樣顯示。

### AC8 甩液（U3）
1. 條件：`state.spin.Holder.dir !== 0`，而且 `Arm{n}.Nozzle{m}` 或 `FixedNozzle{n}` 至少一個 active。Port 不算。
2. 等級：`rpm` 為 0 或無效時為 mid；`rpm < SPLASH.lowRpm` 為 low；`rpm > SPLASH.highRpm` 為 high；其餘為 mid。
3. 停止半徑 `stopR`：從 Cup1 到 Cup4，第一個 `(Master + Slave) / 2 ≥ CUP_RIM.Top[i] − 1` 的 Cup，取其內壁 `CUP_OUTER_R[i] − CUP_WALL`；沒有時取 `CUP_OUTER_R[3]`（Cup4 外壁：沒有 Cup 升起時液滴越過所有 Cup 的上緣，畫到最外層為止）。
4. 液滴模型（固定，不用亂數）：`drops` 個液滴，第 i 個的角度 = Holder 畫面角度 + 2π × i / drops；相位 `p = ((now / SPLASH.periodMs) + i / drops) mod 1`；半徑 = `WAFER_R + p × reach × (stopR − WAFER_R)`；畫成沿半徑方向、長 `length` 的線段，z = `SPLASH.z`。全部放在 `<g id="Splash">` 內，每個液滴一個 `<path>`，所以 `#Splash path` 的數量 = `drops`。
5. 條件不成立時 `#Splash` 為空。

- 頁面 `TARGETS` 與 config 不一致：AC10 讓 build 失敗。
- `localStorage` 過期：
  - Jog 進行中重新整理，頁面顯示上次存的值而不動；之後收到的 `Hold` 會把這個靜止值寫回。
  - 遺失的 `Hold`（`/live` 佇列滿時丟最舊的，`LiveHub.cs:76`）讓存值停在更早的位置。
  - 換瀏覽器或清除資料時，Jog 後的位置回到初始位置。
- IncrementalJog 被 Stop 或 Abort 後，下一次同方向的 IncrementalJog 先走完上次的目標（AC6.3）。
- Unhold 後剩下的距離以完整的 5000 ms 走完，畫面速度變慢（AC6.3）。
