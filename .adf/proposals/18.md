# Proposal #18：Polar2 service 自訂行為第 3 批（Arm 位置與轉速、供液流量、排氣壓力 SVID）

## 1. 目標
#18（https://github.com/KaiJuY/ADS_PLCSimulator/issues/18）：在 `projects/Polar2Chamber/config/service-behaviors.json` 加 62 項，讓 Arm 定位、Jog、IncrementalJog、供液／供氣、Exhaust Fan 在 Execute 期間與 Complete 前寫 SVID。不改程式碼；只用 #16、#17 已有的設定能力（`ecid`、`param`、`constant`、`addParam`、`negate`、`dryRunZero`）。

issue 的驗收條件（AC）以 issue 的編號 1–13 為準，摘要：
- AC1：MoveRecipe、DrainSelect、Damper、SideVent 不進表。
- AC2–AC5：Arm Lift／Rotate 定位（位置 beforeComplete、速度 onEnter／onLeave 0）、IncrementalJog（`addParam`）、Jog±（Speed (Jog)，Negative 取負）。
- AC6：離開 Execute 的定義與重新載入的例外（README 更新）。AC7：共用 SVID 沒有擁有者檢查（README 註明）。
- AC8：19 個供液／供氣 service 寫 `Setpoint`，`dryRunZero`。AC9：Exhaust Fan 寫 Target Pressure，DryRun 不歸零。
- AC10：62 項逐一寫出，不改程式碼。AC11：單元測試（含 86 項、bound 檢查、編號一致性）。AC12：Integration S30–S33。AC13：不量測真 PLC。

名詞與現行行為見 `.adf/proposals/16.md` §1 與 `.adf/proposals/17.md` §1（onEnter／beforeComplete／onLeave 的時機、REAL／DINT 格式、`addParam`、拒絕進入 Execute、bound service）。本 proposal 只補新的部分：
- **bound service**：identity 檔 `projects/Polar2Chamber/plc/ServiceIdentity/F_InitializePolarIIChamberServiceStatus.TcPOU` 以 `F_SetPolarIIChamberServiceIdentity(Status := ServiceStatus.<path>, ServiceId := …, …)` 給 ServiceId ≠ 0 的 service；只寫 `ServiceStatus.<path>.CompletionBehavior := …` 的是 ServiceId 0（未綁定）。Host 的 loader 只檢查 ServiceCtrl 路徑存在（`ServiceBehaviorConfig.cs` `RequireService`）；Core 的 `ModuleRules.Create` 略過未綁定的 key（`ExecuteEntryRules.cs:49-52`），不報錯。
- **Mode**（SVID 1 的文字，`config/service-behaviors.json` 的 `modes`）：0 Disable（只允許 `Chamber.SetMode`）、1 Manual（不允許 `Chamber.SingleProcess`、`Chamber.EMGS`）、2 DryRun（全部允許，`dryRun: true`）、3 Auto。本批的 service 在 Mode 1、2、3 都允許，Mode 0 被拒。
- **重新載入**：在 Editor 或 API 重新載入 `Polar2_ServiceHost` workflow，會把所有 service 重設為 Idle、module 重設為 Execute，不經過離開 Execute，所以 onLeave 不寫（`.adf/proposals/1.md:620`、`projects/Polar2Chamber/README.md:87`、`:110`）。
- **FFU**：Fan Filter Unit（規格書 SVID 63 FFU Speed、64 FFU Pressure）；PLC 沒有 FFU service，記在 #10。
- **Exhaust Fan 的 SupplyFlowPID**：規格書 Service 分頁的 Exhaust Fan_X「Supply Flow (PID)」，說明「搭配差壓計做 PID 控制」，Config Param 是 Target Pressure；所以 service 名稱是 Flow，可觀察的量是差壓（SVID ExhaustFan n Pressure）。
- **DryRun 與排氣**：規格書 Service 分頁 Set Manual Mode 的說明：「Dry Run: 支援所有Service，但僅做Motion，不會出化學藥劑」。#16 Q8 的「流量、壓力歸零」指 Nozzle 的供液／供氣（Flow/Pressure SVID，`Setpoint` 的單位是 ml/sec 或 Pa）；排氣不出化學藥劑，DryRun 照常運轉，所以 Exhaust Fan Pressure 不歸零（issue Q6）。
- **U1**：stage B 的唯一 unit。worktree `../_wt_18-batch3`，base `3847e86`。
