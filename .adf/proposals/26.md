# #26 Proposal：Editor 右側欄 Node 分頁與 PLC Symbol 樹狀選單

## 1. 目標
[#26](https://github.com/KaiJuY/ADS_PLCSimulator/issues/26)：在 Editor 右側欄加入「PLC Variable｜Node」分頁、可拖拉寬度、逐層載入的 Symbol 樹，以及 Node Symbol 參數的選擇對話框。本文的 AC1–AC10 就是 issue #26 的驗收條件編號。

### 1.1 名詞
- **Editor**：`src/AdsPlcSimulator.Host/wwwroot/editor/`，瀏覽器 ES module，沒有建置步驟，入口 `editor.js`。Host 是 ASP.NET Minimal API（`src/AdsPlcSimulator.Host`）。
- **Polar2Chamber**：`projects/Polar2Chamber/`，本 repo 的實際專案，PLC 宣告在 `plc/`。`GVL_Module.Chamber_Control : ARRAY[1..6] OF ST_PolarIIChamber_CtrlStatus`（`plc/Polar2/GVL_Module.TcGVL:6`），該 struct 繼承 `ST_Module_CtrlStatus_Base`，其中 `ModuleConfigParamList : ARRAY[1..500] OF ST_ConfigParamDescriptor`（`Param_Config.MaxConfigParamPerModule = 500`）。專案內最大的陣列長度是 512（`MaxConfigVariableNodes`）。
- **workflow 文件**：`state.doc = { nodes, links, groups }`（`state.js`）。node `{ id, type, x, y, params }`；link（畫布上叫 wire）`{ fromNode, fromPort, toNode, toPort }`；group `{ id, title, x, y, width, height }`。
- **node 定義**：`state.catalog.get(node.type)`，欄位 `title`、`inputs`、`outputs`（port：`{ name, label, kind: 'Exec'|'Data' }`）、`params`（`{ name, label, kind: 'Text'|'Number'|'Choice'|'Symbol', choices, defaultValue }`）。**Data output port** 是 `kind === 'Data'` 的 output。
- **連線參數**：與某個 input port 同名、且該 port 有 link 的參數（`render.js:129`）。
- **選取**：`state.selection` 為 `null`、`{ kind: 'node'|'group', id }` 或 `{ kind: 'link', index }`。
- **執行狀態**：`state.live: Map<nodeId, { status: 'running'|'done'|'failed', outputs: { [port]: value }, error? }>`（`live.js:5-30`）。
- **診斷**：`state.diagnostics: { nodeId: string|null, message }[]`（C# `WorkflowDiagnostic`，`WorkflowCompiler.cs:6`），即 Problems 區的內容。
- **/live 訊息**（`live.js:83-94`）：`flow`（執行事件：`RunStarted`、`NodeStarted`、`NodeCompleted`、`NodeFailed`、`RunCompleted`、`RunFailed`、`RunSkipped`；`RunStarted` 的 nodeId 是 trigger node，`FlowRuntime.cs:166`）；`workflow`（任一 Editor 存檔後的診斷）；`sim`。
- **scope**：root symbol 路徑的第一段，例如 `GVL_Module.Chamber_Control` 的 `GVL_Module`。root 路徑一定有兩段（`SymbolTable.cs:130-135`）。
- **canonical 路徑**：大小寫依宣告，由 `SymbolRef.Path` 產生；查詢不分大小寫。
- **範圍節點**：大陣列的分段，例如 `[1..50]`；以 Path 加 From／To 辨識。
- **前綴節點**：多維陣列尚未填滿的索引，例如 2 維陣列的 `X[1]`。
- 既有 helper 位置：`formatValue`、`readVariable`、`suggestSymbols` 在 `variable.js`；`findNode`、`definitionOf`、`linksTo`、`isInsideGroup` 在 `lookup.js`；`renderAll`、`decorateNode`、`drawWires` 在 `render.js`；`$`、`api` 在 `api.js`（`$` 是 `getElementById`，找不到回 null）。
- **Stage I**：ADF 流程的整合驗證階段，實際啟動 Host 與瀏覽器操作。

## 2. 形狀

### 2.1 Core（`src/AdsPlcSimulator.Core/Plc/SymbolTable.cs`）

```csharp
/// <summary>One entry of a symbol tree level: a scope, a root, a struct member, an array element, an index prefix of a
/// multi-dimensional array, or a range of indices of a large array.</summary>
public sealed record SymbolChild(string Name, string Path, string? Type, bool IsScalar, int? From = null, int? To = null);

public sealed class SymbolTable
{
    public const int ChildPageSize = 50;

    public bool TryGetChildren(string? path, int? from, int? to, out IReadOnlyList<SymbolChild> children, out string? error);

    // 新的私有 helper；EnumerateScalars、SelectMember、SelectElement、TryGetChildren 共用，路徑格式只寫一次：
    private static SymbolRef MemberOf(SymbolRef parent, StructMember member);
    private static SymbolRef ElementOf(SymbolRef parent, ArrayType array, IReadOnlyList<int> indices);
}
```

| 節點 | Name | Path | Type | IsScalar | From／To |
|---|---|---|---|---|---|
| scope | `GVL_Module` | `GVL_Module` | null | false | null |
| root | `Chamber_Control` | `GVL_Module.Chamber_Control` | `PlcType.Name` | `Type.IsScalar` | null |
| struct 成員 | 成員名 | canonical 完整路徑 | `PlcType.Name` | `Type.IsScalar` | null |
| 陣列元素（索引已滿） | `[3]` | `X[1,3]` | 元素型別名 | 元素 `IsScalar` | null |
| 前綴 | `[1]` | `X[1]` | null | false | null |
| 範圍 | `[51..100]` | 父節點的 Path（陣列或前綴） | null | false | 51／100 |

**`TryGetChildren` 演算法**（`from`、`to` 是索引值，含兩端）：
1. `path` 為 null 或空白：`from`、`to` 必須都是 null。回傳 scope：依 `Roots` 順序取第一段，以 `OrdinalIgnoreCase` 去重，保留第一次出現的拼法。
2. `ParsePath(path)` 只有一段名稱（例如 `GVL_Module`、`GVL_Module.`）：當成 scope。`from`、`to` 必須是 null。不分大小寫比對 scope，沒有任何 root 就失敗 `Scope '<path>' is not declared.`。回傳該 scope 的 root，依宣告順序，Name 為 root 路徑第二段。
3. 其他：若最後一段是索引段，先以 `ResolveSegments(path, segments.GetRange(0, segments.Count - 1))` 解析父節點（`List<T>` 不支援範圍索引）；父節點的 `Type.Unaliased` 為 `ArrayType` 且最後一段的索引數少於維度數時，進入**前綴模式**：基底為父節點，前綴為最後一段的索引，每個前綴索引都要在該維度範圍內，否則失敗 `Index <i> is outside [<dimension>] of <type>.`。其餘情況以 `ResolveSegments(path, segments)` 解析整條路徑。前綴只能出現在最後一段；`m[1].x`、`m[1][2]`（2 維）在 `SelectElement` → `OffsetOf` 丟 `ArgumentException` 而失敗。元素型別本身是陣列時，`X[1]` 的索引數等於外層維度數，是完整元素，回傳內層陣列的子項。
4. 解析結果（一律看 `Type.Unaliased`，與 `EnumerateScalars` 相同；`ElementOf` 收到的是 unaliased 的 `ArrayType`。Polar2Chamber 的 `ServiceParam.SetConfig : T_SetConfigParamList` 就是陣列別名）：
   - `StructType`（`Unaliased`）：`from`、`to` 必須是 null。回傳所有成員（`MemberOf`），依宣告順序。成員為 0 個時回傳空清單。
   - `ArrayType`（`Unaliased`）：陣列模式，前綴為空。
   - 其他（純量）：失敗 `'<path>' is <type> and has no children.`。
5. 陣列模式（基底 `b`、陣列 `a`、前綴 `p`，`k = p.Count`）：分段的是第 `k` 維（第一個未填的維度）`d = a.Dimensions[k]`。
   - `from`、`to` 只給一個：失敗 `from and to must be given together.`。
   - 都是 null 且 `d.Length > ChildPageSize`：回傳範圍節點，從 `d.LowerBound` 每 50 個一段，最後一段到 `d.UpperBound`。
   - 都是 null 且 `d.Length <= 50`：範圍為整個維度。
   - 都有值：必須 `d.LowerBound <= from <= to <= d.UpperBound` 且 `to - from + 1 <= 50`，否則失敗 `Range <from>..<to> is outside <d> or longer than 50.`。
   - 每個索引 `i`：`indices = p + [i]`。`k + 1 == 維度數` 時用 `ElementOf(b, a, indices)` 產生元素；否則產生前綴節點，Path 為 `$"{b.Path}[{string.Join(",", indices)}]"`。
   - 範圍節點的 Path：`k == 0` 時為 `b.Path`，否則為 `$"{b.Path}[{string.Join(",", p)}]"`。
6. 例外：捕捉 `SymbolResolutionException`、`ArgumentException`（含 `ArgumentOutOfRangeException`）、`FormatException`、`OverflowException`（`ParsePath` 的 `int.Parse`），回傳 false、`error` 為訊息、`children` 為空陣列。

## 4. 行為

**AC1 分頁**（U2）：`tabs.js` 對 `#variableTab`、`#nodeTab` 接 click → `showTab('variable'|'node')`。`showTab` 切換兩個按鈕的 `.active` 與 `aria-selected`，並設定 `#variablePane`、`#nodePane` 的 `hidden`。CSS 加 `.tab-pane[hidden] { display: none; }`。Problems、Runtime 不動。

**AC2 自動切換**（U2）：
1. `canvas.js` `select(selection)`：現有的 class 切換後呼叫 `renderDetail()`；若 `selection?.kind === 'node'` 再呼叫 `showTab('node')`（即使是同一個 node 也切換）。
2. `renderAll()` 最後送出 `editor:rendered` 事件，`detail.js` 收到後呼叫 `renderDetail()`（同步執行，效果等同直接呼叫）。
3. `renderDetail()` 開頭：選取是 node 且 id 不等於 `shownNodeId` 時呼叫 `showTab('node')`。這涵蓋新增 node（`model.js:15`）、貼上。選取沒變的重畫不切換。Problems 跳轉（`render.js:220-228` `focusNode`）在 `renderAll()` 之後另外呼叫 `showTab('node')`，跳到已選取的同一個 node 時也切換。`showTab` 重複呼叫沒有副作用。
4. 開頁面時預設 PLC Variable；不存上次的分頁。

**AC3 Node 分頁內容**（U2）：`renderDetail()` 依 `state.selection` 更新 `#nodeDetail`。選取 node 時的結構：
```html
<div class="detail-head"><b class="detail-title"></b> <span class="detail-type"></span> <code class="detail-id"></code></div>
<div class="detail-params">
  <div class="detail-param"><label></label><div class="detail-control"><!-- control，U3 加 button.pick --></div></div>
  <div class="detail-param linked"><label></label><div class="detail-linked">← Source1.value</div></div>
</div>
<div class="detail-run"><h3>Run</h3><div class="detail-status"></div><dl class="detail-outputs"></dl></div>
<div class="detail-errors" hidden><h3>Errors</h3><ul></ul></div>
```
1. 標題：`definition.title`（沒有定義時 `node.type`）、`node.type`、`node.id`。
2. 參數：非連線參數每個一列，label 全文（可換行），控制項由 `createParamControl(node, param)` 產生、占滿寬度。
3. 連線參數：不產生控制項，顯示 `← <fromNode>.<fromPort>`（`linksTo(node.id, param.name)[0]`）。
4. 沒有定義的 node：`.detail-params` 以唯讀文字列出 `node.params` 的 `key = value`。
5. 執行（`.detail-run`）：`state.live.get(id)?.status ?? 'not run'`；`<dl>` 列出每個 Data output port 的 `port.label`；`Object.hasOwn(outputs, port.name)` 為 true 時顯示 `formatValue(outputs[port.name])`，否則顯示 `—`（`formatValue(undefined)` 會回 `'null'`，`variable.js:5`；判斷方式同 `decorateNode`，`render.js:68`）。
6. 錯誤（`.detail-errors`）：`state.diagnostics` 中 `nodeId === id` 的 `message`，加上 `live.status === 'failed'` 時的 `live.error`。沒有任何一筆時 `hidden`。
7. **保留焦點**：選取的 node id 等於 `shownNodeId` 且 `document.activeElement` 在 `.detail-params` 內時，`renderDetail()` 只重建 `.detail-head`、`.detail-run`、`.detail-errors`，保留 `.detail-params`。其他情況整個重建。這涵蓋存檔（`editor.js:73`）與 workflow 訊息（`live.js:92`）造成的 `renderAll`。
8. `refreshDetailLive(nodeId?)`：`shownNodeId` 為 null，或有給 `nodeId` 但不等於 `shownNodeId` 時不做事；否則只重建 `.detail-run` 與 `.detail-errors`。`live.js` `applyFlowEvent`：`RunStarted` 分支在重新 decorate 之後呼叫 `refreshDetailLive()`（不帶參數，因為所有 failed 都被重設）；其他分支在 `state.live.set` 之後呼叫 `refreshDetailLive(event.nodeId)`。
9. Problems 同源：診斷改變的兩條路（存檔、workflow 訊息）都呼叫 `renderAll()`，所以 Node 分頁的錯誤與 Problems 同時更新。
10. 選取的 node id 在文件中找不到（已刪除）：顯示提示，`shownNodeId = null`。

**AC4 雙向同步**（U2）：
1. `createParamControl` 給控制項加 `data-param-node = node.id`、`data-param = param.name`。Symbol 的 `suggestSymbols` 處理照舊。
2. 控制項 input 事件改為 `setParam(node, param.name, control.value, control)`（`select` 也觸發 input）。
3. `setParam`：寫 `node.params[name] = value`、`setDirty(true)`；以 `` document.querySelectorAll(`[data-param-node="${CSS.escape(node.id)}"][data-param="${CSS.escape(name)}"]`) `` 找出所有同參數的控制項（含畫布上停用的），除了 `source` 都設 `.value = value`。以程式設定 `.value` 不會觸發 input，所以不會循環。不重畫，輸入中的欄位保持焦點。Number 欄位的行為與現在相同（輸入 `-` 時值為 `''`）。
4. Ctrl+S：`createParamControl` 的 keydown 現在一律 `stopPropagation()`（`render.js:170`），所以在欄位中按 Ctrl+S 會跳出瀏覽器的另存新檔。改為 Ctrl／Cmd+S 不停止傳遞，讓 `editor.js` 處理存檔；其他按鍵照舊停止。畫布與 Node 分頁同時受益。
5. Save 按鈕不變。

**AC5 group、wire、無選取**（U2）：
- group：`.detail-head` 顯示 `group.title` 與 `<n> nodes`（`state.doc.nodes.filter((n) => isInsideGroup(n, group)).length`）。拖拉時數字不即時更新，下次選取或重畫時更新。
- wire、null、找不到的 node：`<p class="detail-empty">Select a node on the canvas</p>`（§11 Q1）。
- 以上 `shownNodeId = null`。

**AC6 寬度**（U2）：
1. CSS：`.layout { grid-template-columns: 210px 1fr 6px var(--sidebar-width, 300px); }`；`.sidebar-resize { cursor: col-resize; background: var(--line); touch-action: none; user-select: none; }`。把手是 grid 的一格，不在側欄的捲動區內，所以不會被捲走。原本 `.sidebar` 的 `border-left` 移除（由把手取代）。
2. `sidebar.js` 載入時：`try { saved = localStorage.getItem(SIDEBAR_WIDTH_KEY) } catch {}`；`Number(saved)` 不是有限數字或 saved 為 null 則 300，否則夾在 300–600；設 `` els.layout.style.setProperty('--sidebar-width', `${w}px`) ``。
3. `#sidebarResize` pointerdown：`preventDefault()`、`setPointerCapture(event.pointerId)`。pointermove（只在 capture 中）：寬度 = `els.layout.getBoundingClientRect().right - event.clientX - 3`（扣掉把手寬度的一半，讓把手中心跟著指標），夾在 300–600 後設定。`lostpointercapture`（pointerup 與 pointercancel 都會觸發）：存 localStorage（try/catch，失敗不處理），`requestAnimationFrame(drawWires)`。

## 8. 考慮過的做法
- 一次載入全部 symbol 建樹：不採用；Polar2Chamber 純量數量大，瀏覽器會卡住（issue）。
- 樹狀選單放進畫布上的 node：不採用；空間不足（issue）。
- Node 的 Symbol 參數直接內嵌樹：不採用；Allen 選對話框（issue 決策紀錄 Q9）。
- 讓 `TryResolve` 接受部分索引：不採用；會改變 `/symbols/value` 的錯誤訊息。前綴只在 `TryGetChildren` 處理。
- 範圍節點再分層：不採用；最大陣列 512 個，一層 11 段已足夠。
- 用 `renderAll` 重建來同步參數：不採用；輸入中的欄位會失去焦點。
- 拖拉把手放在側欄內（絕對定位）：不採用；側欄捲動時把手會被捲走（C17）。
- 對話框驗證輸入的路徑：不採用；畫布欄位也不驗證，錯誤由存檔後的 Problems 顯示，維持一致。
