# Proposal #17：Polar2 service 自訂行為第 2 批（OutsideRing 轉速、Holder MoveModulo、Cup 高度 SVID）

## 1. 目標
#17（https://github.com/KaiJuY/ADS_PLCSimulator/issues/17）：沿用 #16 的 `config/service-behaviors.json`，讓 `ranges` 支援 REAL／LREAL 欄位，新增 SVID 寫入值「目前 SVID 加上 ServiceParam 欄位」，並為 Polar2 的 OutsideRing 轉速、Holder MoveModulo、Cup1–4 的 Top/Middle/Down/IncrementalJog 加上設定。

issue 的驗收條件（AC）：
- AC1：沒有 SVID 的 31 個 service（Gripper、OPR、OutsideRing Lift、Shutter、Cup DecoupleStop、Drainer、Jog±）不進表。
- AC2：OutsideRing CW 進入 Execute 時 SVID 58 = ECID 361，CCW 為負；離開 Execute 寫 0（任何離開，含 Hold、Suspend；Unhold／Unsuspend 再寫 onEnter，同 #16）。
- AC3：`ranges` 支援 REAL、LREAL 欄位，min、max 可為小數，Run 時驗證型別。
- AC4：MoveModulo `Position` 0..360（含兩端）；超出 → MainErrorId 1、Message `Position out of range (0~360).`、Abort；SourceErrorId = 整數部分，負值 `unchecked`；浮點數比較；NaN／∞ 視為超出。
- AC5：MoveModulo 進入 Execute 時 SVID 53 = ECID 318，離開時 0。
- AC6：Cup Top/Middle/Down：Complete 之前，Master、Slave 高度 SVID 寫入對應 ECID（DINT → REAL 文字）。
- AC7：新的寫入值：目前 SVID 值 + ServiceParam 欄位（可取負）；目前值不是數字或不是有限值以 0 計。
- AC8：IncrementalJog：Complete 之前 Master、Slave 各自加上 `Position`，不檢查上下限。
- AC9：DryRun 不影響本批寫入（不標 `dryRunZero`）。
- AC10：4 個 Cup 逐一寫出，共 16 項。
- AC11：單元測試涵蓋 2–9。AC12：Integration S26–S29。AC13：不做真 PLC 量測。

### 2.2 U1 Core：`ExecuteEntryRules.cs`（`ServiceRules`，internal）

範圍在 `ServiceRules.Create` 時依欄位型別分成兩種，`CheckParams` 依種類比較：

```csharp
// replaces List<(SymbolRef Symbol, ParamRange Range)> _ranges
private sealed record ResolvedRange(SymbolRef Symbol, ParamRange Range, bool IsInteger, double Min, double Max);

// in Create: IsInteger = the field type is not REAL or LREAL (the Host allows only integer kinds, REAL and LREAL).
// Min/Max: integer -> range.Min/Max as is; REAL -> (double)(float)range.Min/Max; LREAL -> range.Min/Max as is.

public EntryCheck CheckParams(ProcessImage image)
{
    foreach (ResolvedRange range in _ranges)
    {
        EntryCheck check = range.IsInteger ? CheckInteger(range, image) : CheckReal(range, image);
        if (!check.Passed)
            return check;
    }
    // duration check unchanged
}

// Same as #16: compares and reports the exact long value.
private static EntryCheck CheckInteger(ResolvedRange range, ProcessImage image)
{
    long value = PlcValue.ToInt64(image.ReadValue(range.Symbol));
    long min = (long)range.Min, max = (long)range.Max;
    return value < min || value > max
        ? new EntryCheck(ParamOutOfRangeId, unchecked((uint)value), $"{range.Range.Field} out of range ({min}~{max}).")
        : EntryCheck.Pass;
}

// NaN fails both comparisons, so it is out of range.
private static EntryCheck CheckReal(ResolvedRange range, ProcessImage image)
{
    double value = PlcValue.ToDouble(image.ReadValue(range.Symbol));
    return value >= range.Min && value <= range.Max
        ? EntryCheck.Pass
        : new EntryCheck(ParamOutOfRangeId, SourceErrorId(value), $"{range.Range.Field} out of range ({Text(range.Range.Min)}~{Text(range.Range.Max)}).");
}

private static uint SourceErrorId(double value) =>
    double.IsFinite(value) ? unchecked((uint)(long)Math.Truncate(value)) : uint.MaxValue;

private static string Text(double bound) => bound.ToString(CultureInfo.InvariantCulture);   // 0 -> "0", 0.5 -> "0.5"
```

- 整數欄位：走 `ToInt64` 與 `long` 比較，SourceErrorId、Message 與 #16 完全相同（含 LINT 大值）。Host 保證整數欄位的 min、max 是 ±2^53 內的整數（§2.4），所以 `(long)` 轉換精確，`long` 的 `ToString` 與 #16 的文字相同。
- REAL 欄位：值是 float 轉 double；界線先轉 float 再轉 double，所以 `max = 0.1` 時 client 寫入的 `0.1f` 等於界線、通過（兩端皆含）。Message 用設定檔原本的界線文字。
- LREAL 欄位：值與界線都是 double，直接比較。
- 非有限值（NaN、±∞）SourceErrorId = 4294967295（與「Mode 文字無效」相同的「無法表示」值）。issue AC4 只規定非有限值視為超出，沒有規定 SourceErrorId；截斷 NaN 沒有定義，4294967295 是唯一不會誤導的值。
- 有限但超出 `long` 範圍的值：.NET 9 的 double → long 轉換為飽和（`AdsPlcSimulator.Core.csproj` 是 net9.0），再 `unchecked` 轉 uint。
- −1 < 值 < 0：SourceErrorId 0，Message 區分（issue AC4）。
- `duration` 的檢查不變（`ToInt64`，TIME 是整數毫秒）。

`Number` 的完整新版本（`ParseEcid` 改名 `ParseNumber`，內容不變）：

```csharp
private static double Number(ResolvedWrite write, ProcessImage image, bool dryRun)
{
    if (write.Write.DryRunZero && dryRun)
        return 0;

    SvidValue value = write.Write.Value;
    if (value.Kind == SvidValueKind.AddParam)
        return ParseNumber((string)image.ReadValue(write.Target)) + Step(write, image);   // Negate is applied inside Step only

    double number = value.Kind switch
    {
        SvidValueKind.Param => PlcValue.ToDouble(image.ReadValue(write.Source!.Value)),
        SvidValueKind.Ecid => ParseNumber((string)image.ReadValue(write.Source!.Value)),
        _ => value.Constant,
    };
    return value.Negate && number != 0 ? -number : number;
}

// The field value to add; a NaN or infinite field adds 0.
private static double Step(ResolvedWrite write, ProcessImage image)
{
    double field = PlcValue.ToDouble(image.ReadValue(write.Source!.Value));
    if (!double.IsFinite(field))
        return 0;
    return write.Write.Value.Negate ? -field : field;
}
```

- 目前值：目標 SVID 的 `Value` 文字；不是數字或不是有限值 → 0（issue AC7）。
- 欄位值 NaN／∞ → 加 0，照常寫入「目前值 + 0」（目前值 `"120.0"` 寫回 `"120.0"`；目前值 `"abc"` 寫成 `"0.0"`）。issue 沒有規定欄位非有限值；加 0 讓高度不因無效參數跳動。
- 結果交給現有的 `Format`：REAL SVID 用 `FormatFloat32`；DINT SVID 四捨五入並夾在 int 範圍。REAL 結果超出 float 範圍時 `(float)` 得 ±∞，文字為 `"Infinity"`／`"-Infinity"`；下一次 `AddParam` 讀到它時以 0 為基底（§10）。
- `DryRunZero && dryRun` 時照舊寫 0（本批不標）。
- `ResolveWrite`：`AddParam` 的 source 與 `Param` 相同，是 `$"{param}.{write.Value.Source}"`（switch arm 改成 `SvidValueKind.Param or SvidValueKind.AddParam`）。

驗證（新增或修改的規則；Message 照現有 `{0}: ...` 格式）：
- `RangeRules` 加一條：`min` 或 `max` 不是有限值 → `{0}: min and max must be finite numbers.`（JSON `1e999` 解析成 ∞，見 #16 的 constant 規則）。放在「required」之後、「min is greater than max」之前。
- `BuildRange`：先 `RequireField(...)` 檢查欄位是數字（`IsNumber`，expected 文字 `"an integer or REAL"`，與 param 相同）；`RequireField` 改成回傳解析到的 `SymbolRef`（現有呼叫者忽略回傳值）。再檢查：欄位是整數型別（`IsInteger`）時，min、max 須 `double.IsInteger` 且 `Math.Abs(x) <= 9007199254740992`（2^53），否則 `Fail(where, $"{field} is {type}, so min and max must be integers within ±9007199254740992.")`。順序：型別錯誤先報，界線錯誤後報。
- `WriteRules`：`ValueSourceCount` 加上 `AddParam`；訊息改成 `{0}: value needs exactly one of constant, param, ecid and addParam.`；加一條 `addParam` 空白 → `{0}: addParam is empty.`
- `BuildValue`：`AddParam` 的欄位須是數字（同 param，`"an integer or REAL"`），回傳 `new SvidValue(SvidValueKind.AddParam, 0, field, value.Negate)`。
- `addParam` 的目標 SVID 型別不另限制（DINT 或 REAL 都可，`Svid(..., IsDintOrReal)` 已檢查）。

## 3. 資料與狀態
- 不新增狀態。`ServiceRules` 仍是建好後不變的規則物件；`AddParam` 每次寫入時讀目標 SVID 的目前值，所以多次 IncrementalJog 會累加。

## 4. 行為（每條 AC 的路徑）
- AC1：設定檔沒有這些 key → `ModuleRules.For` 回 `ServiceRules.None` → 只有 Mode 檢查（#16 AC3）。
- AC2：`OutsideRing.Rotate.MoveVelocityCW` 進 Execute → `WriteOnEnter`：讀 ECID 361 文字 → `ParseNumber` → DINT 文字寫 SVID 58；CCW `Negate`。離開 → `WriteOnLeave` 寫 `"0"`。
- AC3、AC4：Run → `BuildRange` 接受 LREAL `Position`；進 Execute → `CheckParams` → `CheckReal` → 400 → `EntryCheck(1, 400, "Position out of range (0~360).")` → 拒絕進入 Execute（§1）→ 下一次 scan Aborted。

## 10. 風險
- `ParamRange` 的 public 簽名改變：外部程式若用 `long` 具名參數或 deconstruct 成 `long` 會編譯失敗。repo 內沒有這種用法。
- 整數欄位的界線限制在 ±2^53（設定檔驗證）；整數欄位的比較與 SourceErrorId 仍以 `long` 計算，不受影響。
